## ГЛАВА 4. ВЕРОЯТНОСТНЫЕ СТРУКТУРЫ ДАННЫХ

### 4.1 Введение в вероятностные структуры данных

Сбалансированные деревья поиска (AVL, красно-чёрные) обеспечивают гарантированную логарифмическую сложность ценой явных инвариантов и нетривиальных процедур восстановления баланса: ротаций, перекраски, отслеживания высоты или цвета в каждом узле. Хеш-таблицы достигают $O(1)$ за счёт полного отказа от упорядоченности. Вероятностные структуры данных предлагают альтернативу: балансировка достигается не детерминированно, а с высокой вероятностью, путём внесения управляемой случайности непосредственно в алгоритм. Благодаря этому реализация оказывается существенно проще детерминированных аналогов при схожей ожидаемой асимптотике.

Ключевое свойство вероятностных структур: при фиксированном входе данных поведение алгоритма определяется как ключами, так и исходом встроенного источника случайности. Это означает, что все оценки сложности, помимо $W(n)$ и $B(n)$, являются ожидаемыми по распределению случайных решений алгоритма, а не по распределению входных данных.

В рамках данной работы реализованы две вероятностные структуры данных: `TreapDictionary<TKey, TValue>` (декартово дерево) и `SkipListDictionary<TKey, TValue>` (список с пропусками). Обе реализуют словарный интерфейс с операциями `ContainsKey`, `GetValue`, `TryGetValue`, `Add`, `InsertOrAssign`, `Remove`, `Clear` и `Count`.

#### Генератор псевдослучайных чисел (XorShift64*)

Обе структуры используют один и тот же встроенный ГПСЧ на основе XorShift64* — быстрый некриптографический генератор с периодом $2^{64} - 1$. Состояние генератора хранится в поле `_rngState` типа `uint64_t` и инициализируется из `std::random_device` при создании объекта; если `std::random_device` вернул 0, состояние устанавливается в фиксированную ненулевую константу $\texttt{0x9e3779b97f4a7c15}$, исключая вырожденный случай.

Шаг генератора:
$$x \leftarrow x \oplus (x \gg 12), \quad x \leftarrow x \oplus (x \ll 25), \quad x \leftarrow x \oplus (x \gg 27), \quad \text{return}\ x \cdot c$$

где $c = \texttt{0x2545F4914F6CDD1D}$ — мультипликативная константа финализации из семейства splitmix64. Три операции xor со сдвигами обеспечивают полный период и равномерное распределение; умножение улучшает статистику младших бит.

### 4.2 Treap (декартово дерево)

Декартово дерево (Treap — TRee + hEAP) — вероятностная структура данных, представляющая собой двоичное дерево поиска по ключам и одновременно кучу (max-heap) по случайным приоритетам. Структура поддерживает два инварианта:

> **Treap-инварианты.**
> 1. **BST-инвариант:** для каждого узла $x$ все ключи левого поддерева строго меньше $x.key$, все ключи правого поддерева строго больше $x.key$.
> 2. **Max-heap-инвариант:** для каждого узла $x$: $x.priority \ge \mathrm{left}(x).priority$ и $x.priority \ge \mathrm{right}(x).priority$.

Два инварианта однозначно определяют форму дерева при фиксированных ключах и попарно различных приоритетах (доказывается индукцией по $n$). При случайных независимых равномерно распределённых приоритетах треап эквивалентен случайному BST, построенному последовательной вставкой ключей в случайном порядке. Приоритеты имеют тип `uint32_t` и вычисляются генератором XorShift64*.

**Теорема (ожидаемая глубина узла в треапе).** Пусть $n$ узлов треапа имеют ключи $k_1 < k_2 < \ldots < k_n$; узел с ключом $k_r$ имеет ранг $r$. Тогда ожидаемая глубина этого узла (число узлов на пути от корня до него включительно) равна:

$$E\!\left[\mathrm{depth}(x_r)\right] = H_r + H_{n-r+1} - 1,$$

где $H_k = \sum_{i=1}^{k} \tfrac{1}{i}$ — $k$-е гармоническое число. В частности, $E\!\left[\mathrm{depth}(x_r)\right] \le 2H_n - 1 < 2\ln n + 1 = O(\log n)$.

**Доказательство.** Введём индикаторную случайную величину $A_{jr} = 1$, если узел $x_j$ является предком узла $x_r$. Тогда:

$$\mathrm{depth}(x_r) = 1 + \sum_{j \ne r} A_{jr}.$$

**Лемма.** Узел $x_j$ является предком $x_r$ тогда и только тогда, когда $x_j$ имеет наибольший приоритет среди всех узлов с рангами в интервале $[\min(j, r),\, \max(j, r)]$.

*Доказательство.* Из однозначности треапа: узел с максимальным приоритетом на отрезке рангов $[a, b]$ является корнем поддерева, содержащего все узлы этого отрезка. Следовательно, он обязательно встречается на любом пути от корня к $x_r$, если $r \in [a, b]$. $\square$

Поскольку приоритеты независимы и равномерно распределены, по лемме:

$$P\!\left[A_{jr} = 1\right] = \frac{1}{|j - r| + 1}.$$

Тогда:

$$E\!\left[\mathrm{depth}(x_r)\right] = 1 + \sum_{j \ne r} \frac{1}{|j-r|+1} = 1 + \sum_{s=1}^{r-1} \frac{1}{r-s+1} + \sum_{s=r+1}^{n} \frac{1}{s-r+1}.$$

Первая сумма: замена $t = r - s + 1$ ($s: 1 \to r-1$, $t: r \to 2$):

$$\sum_{s=1}^{r-1} \frac{1}{r-s+1} = \sum_{t=2}^{r} \frac{1}{t} = H_r - 1.$$

Вторая сумма: замена $t = s - r + 1$ ($s: r+1 \to n$, $t: 2 \to n-r+1$):

$$\sum_{s=r+1}^{n} \frac{1}{s-r+1} = \sum_{t=2}^{n-r+1} \frac{1}{t} = H_{n-r+1} - 1.$$

Итого:

$$E\!\left[\mathrm{depth}(x_r)\right] = 1 + (H_r - 1) + (H_{n-r+1} - 1) = H_r + H_{n-r+1} - 1. \quad \square$$

Так как $H_r \le H_n$ и $H_{n-r+1} \le H_n$, получаем $E\!\left[\mathrm{depth}(x_r)\right] \le 2H_n - 1 < 2\ln n + 1$, откуда $E[h] = O(\log n)$.

---

Реализован класс `TreapDictionary<TKey, TValue>` на основе узлов `detail::TreapNode<TKey, TValue>`. Каждый узел хранит `std::pair<TKey, TValue> data`, `uint32_t priority`, `TreapNode* left`, `TreapNode* right`.

**Процедура 4.2.1. Random Priority**
```basic
01: RandomPriorityImpl()
02:     x = _rngState
03:     x = x XOR (x >> 12)
04:     x = x XOR (x << 25)
05:     x = x XOR (x >> 27)
06:     _rngState = x
07:     x = x * 0x2545F4914F6CDD1D
08:     return uint32_t(x XOR (x >> 32))
```

- **Входные данные:** нет (использует внутреннее поле `_rngState`).

**Шаги алгоритма:**
1. Выполняется шаг XorShift64: три операции xor со сдвигами 12, 25, 27 — стандартные параметры, обеспечивающие максимальный период $2^{64} - 1$.
2. Обновляется состояние `_rngState`.
3. Результат умножается на мультипликативную константу.
4. Возвращается `uint32_t`: финальный xor с 32-битным сдвигом перемешивает старшую и младшую половины, улучшая качество бит.

**Анализ сложности:**

Фиксированное число арифметических операций, не зависящее от $n$:

$$W(n) = B(n) = A(n) = \Theta(1)$$

**Процедура 4.2.2. Init Node**
```basic
01: InitNodeImpl(key, value)
02:     priority = RandomPriorityImpl()
03:     return new Node{data = (key, value), priority, left = NIL, right = NIL}
```

- **Входные данные:** `key` — ключ; `value` — значение.

**Шаги алгоритма:**
1. Генерируется случайный приоритет через `RandomPriorityImpl`.
2. Выделяется память (`new Node`); заполняются поля данных, приоритета и обнуляются указатели на потомков.

**Анализ сложности:**

Одно обращение к ГПСЧ ($\Theta(1)$) и одна аллокация ($\Theta(1)$):

$$W(n) = B(n) = A(n) = \Theta(1)$$

---

**Процедура 4.2.3. Rotate Right**
```basic
01: RotateRightImpl(node)
02:     left = node.left
03:     node.left = left.right
04:     left.right = node
05:     return left
```

- **Входные данные:** `node` — корень поддерева, у которого нарушен max-heap-инвариант: $\mathrm{left}(node).priority > node.priority$.

**Шаги алгоритма:**
1. Левый потомок `left` становится новым корнем поддерева.
2. Правое поддерево `left` (с ключами в интервале $(\mathrm{left.key},\, node.key)$) становится левым поддеревом `node`.
3. `node` становится правым потомком `left`.

**Корректность.** BST-инвариант сохраняется: ключи поддерева `left.left` < `left.key` < ключи бывшего `left.right` < `node.key` < ключи `node.right`. Max-heap-инвариант восстанавливается: `left` (с бо́льшим приоритетом) поднимается над `node`.

**Анализ сложности:**

Три переприсваивания указателей:

$$W(n) = B(n) = A(n) = \Theta(1)$$

---

**Процедура 4.2.4. Rotate Left**
```basic
01: RotateLeftImpl(node)
02:     right = node.right
03:     node.right = right.left
04:     right.left = node
05:     return right
```

- **Входные данные:** `node` — корень поддерева, у которого $\mathrm{right}(node).priority > node.priority$.

**Шаги алгоритма:** симметричны процедуре 4.2.3.

**Анализ сложности:**

$$W(n) = B(n) = A(n) = \Theta(1)$$

---

**Процедура 4.2.5. Find**
```basic
01: FindImpl(node, key)
02:     while node ≠ NIL do
03:         if key < node.key then
04:             node = node.left
05:         else if node.key < key then
06:             node = node.right
07:         else
08:             return node
09:     return NIL
```

- **Входные данные:** `node` — начальный узел (при публичном вызове — корень); `key` — искомый ключ.

**Шаги алгоритма:**
1. Итеративный спуск по BST-инварианту: на каждом шаге ровно два сравнения.
2. Если ключ совпадает — возвращается указатель на узел.
3. Если достигнут NIL — ключ отсутствует.

**Замечание.** В отличие от AVL/RBT, где `_find` реализован рекурсивно, данная реализация использует итерацию: это исключает накладные расходы на стек вызовов и потенциальный stack overflow при глубоких деревьях.

**Анализ сложности:**

Каждая итерация опускается на один уровень; глубина спуска не превышает $h$.

*Худший случай* — ключ отсутствует или находится на максимальной глубине; при катастрофически неудачных приоритетах $h = n - 1$:

$$W(n) = O(n)$$

*Лучший случай* — ключ совпадает с ключом корня:

$$B(n) = \Theta(1)$$

*Ожидаемый случай* — по теореме $E[h] = O(\log n)$:

$$A(n) = O(\log n)$$

---

**Процедура 4.2.6. Insert**
```basic
01: InsertImpl(node, key, value, inserted)
02:     if node = NIL then
03:         inserted = true
04:         return InitNodeImpl(key, value)
05:
06:     if key < node.key then
07:         node.left = InsertImpl(node.left, key, value, inserted)
08:         if inserted and node.left.priority > node.priority then
09:             node = RotateRightImpl(node)
10:     else if node.key < key then
11:         node.right = InsertImpl(node.right, key, value, inserted)
12:         if inserted and node.right.priority > node.priority then
13:             node = RotateLeftImpl(node)
14:
15:     return node
```

- **Входные данные:** `node` — текущий узел; `key`, `value` — вставляемая пара; `inserted` — выходной флаг.

**Шаги алгоритма:**
1. Если узел NIL — создаётся новый лист через `InitNodeImpl`, `inserted = true`.
2. Рекурсивный спуск по BST-инварианту влево или вправо.
3. На обратном пути: если приоритет вставленного потомка превышает приоритет текущего узла — выполняется соответствующая ротация для восстановления max-heap-инварианта.
4. Если ключ уже существует (ни одна из двух ветвей `if` не сработала) — возвращается `node` без изменений; `inserted` остаётся `false`.

**Замечание.** При вставке нового узла достаточно не более одной ротации на всём пути возврата. Рассмотрим путь от корня до вставленного листа: ротация выполняется только в первом узле, где нарушается heap-инвариант. После ротации этот узел (с меньшим приоритетом) опускается вниз, а его предок (новый корень поддерева) имеет бо́льший приоритет, чем свой предок в исходном дереве — heap-инвариант выше уже соблюдался и продолжает соблюдаться. Таким образом, в отличие от AVL, нет каскадных ротаций.

**Анализ сложности:**

Спуск — $d$ уровней; обратный путь — $d$ проверок и не более одной ротации $\Theta(1)$:

$$T(n) = \Theta(d) \le \Theta(h)$$

*Худший случай:* $W(n) = O(n)$

*Лучший случай* — дерево пусто, узел становится корнем: $B(n) = \Theta(1)$

*Ожидаемый случай:* $A(n) = O(\log n)$

**Процедура 4.2.7. Remove (внутренний)**
```basic
01: RemoveImpl(node, key, removed)
02:     if node = NIL then return NIL
03:
04:     if key < node.key then
05:         node.left = RemoveImpl(node.left, key, removed)
06:         return node
07:
08:     if node.key < key then
09:         node.right = RemoveImpl(node.right, key, removed)
10:         return node
11:
12:     // Ключ найден
13:     removed = true
14:
15:     if node.left = NIL then
16:         right = node.right
17:         delete node
18:         return right
19:
20:     if node.right = NIL then
21:         left = node.left
22:         delete node
23:         return left
24:
25:     // Оба потомка существуют: ротацией опускаем узел вниз
26:     if node.left.priority > node.right.priority then
27:         node = RotateRightImpl(node)
28:         node.right = RemoveImpl(node.right, key, removed)
29:     else
30:         node = RotateLeftImpl(node)
31:         node.left = RemoveImpl(node.left, key, removed)
32:
33:     return node
```

- **Входные данные:** `node` — текущий узел; `key` — удаляемый ключ; `removed` — выходной флаг.

**Шаги алгоритма:**
1. Если узел NIL — ключ не найден, `removed` остаётся `false`.
2. Рекурсивный спуск влево или вправо по BST-инварианту.
3. При нахождении узла: если у него не более одного потомка — он заменяется этим потомком (стандартное удаление из BST); узел удаляется.
4. Если оба потомка существуют: выполняется ротация того потомка, у которого бо́льший приоритет — это «опускает» удаляемый узел на один уровень вниз, сохраняя heap-инвариант для остальных узлов. Рекурсивный вызов продолжает опускать его, пока у него не окажется не более одного потомка.

**Корректность.** Ротация потомка с бо́льшим приоритетом поднимает его на место удаляемого узла, сохраняя heap-инвариант в корне поддерева. BST-инвариант сохраняется ротациями (аналогично 4.2.3–4.2.4). На каждом уровне после ротации удаляемый узел оказывается ниже, пока не достигнет листового положения и не будет удалён.

**Анализ сложности:**

Спуск до найденного узла — $d_1$ уровней. Опускание через ротации — ещё $d_2 \le h - d_1$ шагов. На каждом уровне — $\Theta(1)$ работы.

*Худший случай:* $W(n) = O(h) = O(n)$

*Лучший случай* — ключ не найден, первый вызов возвращает NIL: $B(n) = \Theta(1)$

*Ожидаемый случай:* $A(n) = O(\log n)$

**Процедура 4.2.8. Contains Key**
```basic
01: ContainsKeyImpl(key)
02:     return FindImpl(Root, key) ≠ NIL
```

- **Входные данные:** `key` — ключ, наличие которого проверяется.

**Шаги алгоритма:**
1. Вызывается `FindImpl(Root, key)`.
2. Если результат не NIL — возвращается `true`, иначе — `false`.

**Анализ сложности:**

$$W(n) = O(n), \quad B(n) = \Theta(1), \quad A(n) = O(\log n)$$

**Процедура 4.2.9. Try Get Value**
```basic
01: TryGetValueImpl(key, value)
02:     node = FindImpl(Root, key)
03:     if node = NIL then return false
04:     value = node.data.second
05:     return true
```

- **Входные данные:** `key` — искомый ключ; `value` — выходной параметр, в который записывается найденное значение.

**Шаги алгоритма:**
1. Вызывается `FindImpl(Root, key)`.
2. Если узел не найден — возвращается `false`.
3. Найденное значение записывается в `value`, возвращается `true`.

**Анализ сложности:**

Стоимость определяется вызовом `FindImpl`; все остальные операции — $\Theta(1)$:

$$W(n) = O(n), \quad B(n) = \Theta(1), \quad A(n) = O(\log n)$$

**Процедура 4.2.10. Get Value**
```basic
01: GetValueImpl(key)
02:     node = FindImpl(Root, key)
03:     if node = NIL then raise KeyNotFoundException
04:     return node.data.second
```

- **Входные данные:** `key` — искомый ключ.

**Шаги алгоритма:**
1. Вызывается `FindImpl(Root, key)`.
2. Если узел не найден — генерируется исключение `KeyNotFoundException`.
3. Возвращается ссылка на значение.

**Анализ сложности:**

$$W(n) = O(n), \quad B(n) = \Theta(1), \quad A(n) = O(\log n)$$

**Процедура 4.2.11. Add**
```basic
01: AddImpl(key, value)
02:     if FindImpl(Root, key) ≠ NIL then
03:         raise DuplicateKeyException
04:     inserted = false
05:     Root = InsertImpl(Root, key, value, inserted)
06:     if inserted then Count = Count + 1
```

- **Входные данные:** `key` — ключ; `value` — значение.

**Шаги алгоритма:**
1. Проверяется отсутствие ключа через `FindImpl`.
2. Если ключ существует — генерируется `DuplicateKeyException`.
3. Иначе вызывается `InsertImpl`; при успехе счётчик увеличивается.

### 4.3 Список с пропусками

Список с пропусками (Skip List) — вероятностная структура данных, реализующая упорядоченный словарь на основе многоуровневых связных списков. На уровне 0 присутствуют все $n$ элементов в отсортированном по ключам порядке. Каждый следующий уровень $l$ содержит случайно выбранное подмножество уровня $l-1$: каждый элемент независимо «продвигается» на уровень выше с вероятностью $p = \tfrac{1}{2}$.

Поиск начинается с наибольшего заполненного уровня и движется вправо (до элемента с ключом $\ge$ искомого), затем спускается на уровень ниже. Это позволяет пропускать большие участки списка на верхних уровнях, аналогично двоичному поиску.

Структура поддерживает $L_{\max} + 1$ уровней (от 0 до $L_{\max}$, где $L_{\max} = $ `DTR_SKIPLIST_MAX_LEVEL` — compile-time константа). Массив `_head[0 \ldots L_{\max}]$ хранит первые узлы каждого уровня; переменная `_level` ($-1$ при пустом списке) хранит текущий максимальный заполненный уровень. Каждый узел содержит `std::pair<TKey, TValue> data`, `uint8_t level` и массив `forward[0..L_max]` (указатель `forward[l]` ведёт к следующему узлу на уровне $l$).

**Управление памятью.** Для снижения стоимости аллокации реализован пул узлов (`_pool`) и список свободных узлов (`_freeList`). При выделении нового узла сначала проверяется `_freeList`; при его отсутствии узел создаётся в `_pool` через `emplace_back`. При освобождении узел возвращается в голову `_freeList`, используя `forward[0]` как указатель следующего элемента списка.

**Путь обновления (update path).** Вспомогательная структура `UpdatePath` — массив $L_{\max} + 1$ указателей, где `update[l]` — последний узел на уровне $l$, чей ключ строго меньше целевого. Этот массив заполняется при каждом вызове `_search` и используется операциями вставки и удаления.

**Теорема (ожидаемое время поиска в списке с пропусками).** В списке с пропусками из $n$ элементов с параметром $p = \tfrac{1}{2}$ ожидаемое число сравнений при поиске не превышает $2\log_2 n + O(1)$.

**Доказательство (метод обратного анализа, Pugh 1990).** Рассмотрим поисковый путь в обратном направлении — от конечной позиции (найденного или несуществующего элемента) к голове списка. В каждой точке обратного пути возможны два события:

- **Подъём** (переход на уровень выше): возможен тогда и только тогда, когда текущий узел присутствует на следующем уровне.
- **Шаг назад** (движение к предшественнику на том же уровне): выполняется при невозможности подъёма.

Поскольку уровень каждого узла определяется геометрическим распределением с параметром $p = \tfrac{1}{2}$, вероятность подъёма в произвольной точке пути равна $p = \tfrac{1}{2}$, а вероятность шага назад — $\tfrac{1}{2}$.

Обозначим через $C(k)$ ожидаемое число шагов при подъёме с уровня 0 до уровня $k$:

$$C(0) = 0, \qquad C(k) = \tfrac{1}{2}(1 + C(k)) + \tfrac{1}{2}(1 + C(k-1)).$$

Решение рекуррентности: $C(k) = 2k$. При $k = L_{\max} = \lfloor\log_2 n\rfloor$ получаем ожидаемое число шагов, не превышающее $2\log_2 n + O(1)$. $\square$

Реализован класс `SkipListDictionary<TKey, TValue>`.

**Процедура 4.3.1. Next Random**
```basic
01: NextRandomImpl()
02:     x = _rngState
03:     x = x XOR (x >> 12)
04:     x = x XOR (x << 25)
05:     x = x XOR (x >> 27)
06:     _rngState = x
07:     return x * 0x2545F4914F6CDD1D
```

- **Входные данные:** нет (использует поле `_rngState`).

**Шаги алгоритма:**
1. Шаг XorShift64: три операции xor со сдвигами.
2. Обновляется `_rngState`.
3. Результат умножается на мультипликативную константу и возвращается как полное 64-битное значение.

**Отличие от `RandomPriority` (Treap).** В треапе финализация дополнительно включает `x XOR (x >> 32)`, сворачивающий результат в `uint32_t`. Здесь возвращается полный `uint64_t`, так как `RandomLevel` использует его биты независимо.

**Анализ сложности:**

$$W(n) = B(n) = A(n) = \Theta(1)$$

**Процедура 4.3.2. Random Level**
```basic
01: RandomLevelImpl()
02:     bits = NextRandomImpl()
03:     level = 0
04:     mask = 1
05:
06:     while level < DTR_SKIPLIST_MAX_LEVEL and (bits AND mask) ≠ 0 do
07:         level = level + 1
08:         mask = mask << 1
09:
10:     return level
```

- **Входные данные:** нет.

**Шаги алгоритма:**
1. Генерируется 64-битное псевдослучайное значение `bits`.
2. Проверяются последовательные биты 0, 1, 2, … с помощью сдвигаемой маски.
3. Подсчитывается число подряд идущих единичных бит начиная с бита 0; результат ограничивается $L_{\max}$.

**Анализ распределения.** Поскольку биты 64-битного псевдослучайного числа независимы и равновероятны:

$$P[\mathrm{level} = k] = \begin{cases} (1/2)^{k+1} & 0 \le k < L_{\max} \\ (1/2)^{L_{\max}} & k = L_{\max} \end{cases}$$

Это усечённое геометрическое распределение с параметром $p = \tfrac{1}{2}$. Ожидаемый уровень: $E[\mathrm{level}] = \sum_{k=1}^{L_{\max}} (1/2)^k \cdot k < 2$.

**Анализ сложности:**

Цикл выполняется не более $L_{\max}$ итераций; $L_{\max} = \mathrm{const}$:

$$W(n) = B(n) = A(n) = \Theta(1)$$

**Процедура 4.3.3. Alloc Node**
```basic
01: AllocNodeImpl(key, value, nodeLevel)
02:     if _freeList ≠ NIL then
03:         node = _freeList
04:         _freeList = _freeList.forward[0]
05:     else
06:         _pool.emplace_back(key, value, nodeLevel)
07:         node = &_pool.back()
08:
09:     node.data = (key, value)
10:     node.level = nodeLevel
11:     node.forward.fill(NIL)
12:     return node
```

- **Входные данные:** `key`, `value` — данные узла; `nodeLevel` — уровень узла.

**Шаги алгоритма:**
1. Если `_freeList` непуст — из его головы извлекается готовый узел; `_freeList` продвигается вперёд через `forward[0]`.
2. Иначе создаётся новый узел в `_pool` через `emplace_back`.
3. Поля узла устанавливаются; все `forward`-указатели обнуляются.

**Анализ сложности:**

Путь через `_freeList` — $\Theta(1)$; путь через `_pool.emplace_back` — амортизированно $\Theta(1)$:

$$W(n) = B(n) = A(n) = \Theta(1) \text{ (амортизированно)}$$

$$W(n) = B(n) = A(n) = \Theta(1)$$

**Процедура 4.3.5. Search**
```basic
01: SearchImpl(key, update)
02:     update.fill(NIL)
03:     if _level < 0 then return NIL
04:
05:     predecessor = NIL
06:
07:     for level from _level down to 0 do
08:         next = if predecessor ≠ NIL then predecessor.forward[level]
09:                else _head[level]
10:
11:         while next ≠ NIL do
12:             prefetch(next.forward[level])    // подсказка процессору для предзагрузки в кэш
13:             if next.data.first < key then
14:                 predecessor = next
15:                 next = predecessor.forward[level]
16:             else
17:                 break
18:
19:         update[level] = predecessor
20:
21:     candidate = if predecessor ≠ NIL then predecessor.forward[0]
22:                 else _head[0]
23:
24:     if candidate ≠ NIL and candidate.data.first = key then
25:         return candidate
26:     return NIL
```

- **Входные данные:** `key` — целевой ключ; `update` — выходной массив предшественников (путь обновления).

**Шаги алгоритма:**
1. Если список пуст (`_level < 0`) — немедленный возврат NIL.
2. Цикл спуска: от уровня `_level` до уровня 0.
3. На каждом уровне `next` движется вправо, пока `next.key < key`; `predecessor` фиксирует последний пройденный узел. При переходе на уровень ниже `predecessor` не сбрасывается — поиск продолжается с той же позиции.
4. `update[level] = predecessor` сохраняется для последующих операций вставки/удаления.
5. На уровне 0 проверяется `predecessor.forward[0]` (или `_head[0]`): совпадение ключа означает успешный поиск.
6. Инструкция `prefetch` подсказывает процессору заранее загрузить следующий узел в кэш-память, снижая задержки при сканировании.

**Анализ сложности:**

Число шагов определяется структурой поискового пути.

*Худший случай* — все $n$ элементов имеют уровень 0, поиск на уровне 0 перебирает весь список:

$$W(n) = O(n)$$

*Лучший случай* — искомый ключ является первым элементом на уровне `_level`:

$$B(n) = \Theta(1)$$

*Ожидаемый случай* — по теореме раздела 4.3:

$$A(n) = O(\log n)$$

**Процедура 4.3.6. Link Node**
```basic
01: LinkNodeImpl(node, update, nodeLevel)
02:     for level from 0 to nodeLevel do
03:         predecessor = update[level]
04:         if predecessor ≠ NIL then
05:             node.forward[level] = predecessor.forward[level]
06:             predecessor.forward[level] = node
07:         else
08:             node.forward[level] = _head[level]
09:             _head[level] = node
```

- **Входные данные:** `node` — вставляемый узел; `update` — путь обновления из `SearchImpl`; `nodeLevel` — уровень узла.

**Шаги алгоритма:**
1. Для каждого уровня от 0 до `nodeLevel`: `node` вставляется между `update[level]` и его следующим элементом.
2. Если `update[level] = NIL` — `node` вставляется в начало уровня (обновляется `_head[level]`).

**Анализ сложности:**

Цикл выполняется `nodeLevel + 1` итераций; $E[\mathrm{nodeLevel}] < 2$; $L_{\max} = \mathrm{const}$:

$$W(n) = B(n) = A(n) = \Theta(1)$$

```basic
01: InsertOrAssignImpl(key, value)
02:     update = new UpdatePath
03:     found = SearchImpl(key, update)
04:
05:     if found ≠ NIL then
06:         found.data.second = value
07:         return
08:
09:     nodeLevel = RandomLevelImpl()
10:     if nodeLevel > _level then
11:         for level from _level + 1 to nodeLevel do
12:             update[level] = NIL
13:         _level = nodeLevel
14:
15:     node = AllocNodeImpl(key, value, nodeLevel)
16:     LinkNodeImpl(node, update, nodeLevel)
17:     Count = Count + 1
```

- **Входные данные:** `key` — ключ; `value` — значение.

**Шаги алгоритма:**
1. Выполняется `SearchImpl`.
2. Если ключ найден — значение обновляется на месте без изменения структуры и счётчика.
3. Если не найден — выполняется вставка нового узла аналогично `Add`.

**Анализ сложности:**

$$W(n) = O(n), \quad B(n) = \Theta(1), \quad A(n) = O(\log n)$$

---

**Процедура 4.3.14. Remove**
```basic
01: RemoveImpl(key)
02:     if _level < 0 then return false
03:
04:     update = new UpdatePath
05:     node = SearchImpl(key, update)
06:     if node = NIL then return false
07:
08:     UnlinkNodeImpl(node, update)
09:     FreeNodeImpl(node)
10:     ShrinkLevelImpl()
11:     Count = Count - 1
12:     return true
```

- **Входные данные:** `key` — удаляемый ключ.

**Шаги алгоритма:**
1. Если список пуст (`_level < 0`) — немедленный возврат `false`.
2. Выполняется `SearchImpl`; если не найден — `false`.
3. Найденный узел исключается из всех уровней через `UnlinkNodeImpl`.
4. Узел возвращается в пул через `FreeNodeImpl`.
5. `ShrinkLevelImpl` уменьшает `_level`, если верхний уровень опустел.
6. Счётчик уменьшается.

**Анализ сложности:**

$$W(n) = O(n), \quad B(n) = \Theta(1), \quad A(n) = O(\log n)$$

---

**Процедура 4.3.15. Clear**
```basic
01: ClearImpl()
02:     _head.fill(NIL)
03:     _level = -1
04:     Count = 0
05:     _pool.clear()
06:     _pool.shrink_to_fit()
07:     _freeList = NIL
```

- **Входные данные:** нет.

**Шаги алгоритма:**
1. Все указатели `_head` обнуляются ($O(L_{\max}) = O(1)$).
2. `_level = -1`, счётчик обнуляется.
3. `_pool.clear()` уничтожает все $n$ объектов-узлов, вызывая их деструкторы.
4. `_pool.shrink_to_fit()` освобождает выделенную под пул память.
5. `_freeList = NIL`.

**Замечание.** В отличие от `TreapDictionary::Clear`, которая обходит дерево рекурсивно, данная реализация пользуется тем, что все узлы хранятся в `_pool`: очистка выполняется одним вызовом `_pool.clear()` без обхода структуры.

**Анализ сложности:**

`_pool.clear()` уничтожает $n$ объектов:

$$W(n) = B(n) = A(n) = \Theta(n)$$

---

**Процедура 4.3.16. Count**
```basic
01: CountImpl()
02:     return Count
```

**Анализ сложности:**

$$W(n) = B(n) = A(n) = \Theta(1)$$

---

### 4.4 Тестирование производительности

Для оценки практической эффективности разработанных реализаций было проведено сравнительное тестирование производительности. В качестве эталонной реализации использовался стандартный контейнер `std::map` из стандартной библиотеки C++, реализованный на основе красно-чёрного дерева. Каждая тестируемая структура данных сравнивалась с эталоном в двух сценариях.

**Условия тестирования:**
- **Инициализация (Init):** последовательная вставка $N$ пар ключ–значение; фиксируется суммарное время заполнения структуры.
- **Чтение (Read):** серия операций поиска по ключам; фиксируется среднее время одной операции в наносекундах.

---

**Таблица 4.4.1. SkipList vs std::map ($N = 100\,000$)**

| Операция | `std::map` | `SkipListDictionary` | Преимущество |
|---|:---:|:---:|:---:|
| Инициализация | ~130 мс | ~242 мс | `std::map` в 1,85× быстрее |
| Чтение | ~1 135 нс/оп | ~1933 нс/оп | `std::map` в 1,70× быстрее |
| ContainsKey | ~1 209 нс/оп | ~2003 нс/оп | `std::map` в 1,66× быстрее |
| Insert | ~14 303 нс/оп | ~21586 нс/оп | `std::map` в 1,50× быстрее |
| Итерация | ~190 нс/оп | ~179 нс/оп | `SkipListDictionary` в **1,06×** быстрее |

---

**Таблица 4.4.2. TreapDictionary vs std::map ($N = 100\,000$)**

| Операция | `std::map` | `TreapDictionary` | Преимущество |
|---|:---:|:---:|:---:|
| Инициализация | ~110 мс | ~266 мс | `std::map` в 2,40× быстрее |
| Чтение | ~1111 нс/оп | ~1016 нс/оп | `TreapDictionary` в **1,09×** быстрее |
| ContainsKey | ~797 нс/оп | ~1002 нс/оп | `std::map` в 1,25× быстрее |
| Итерация | ~161 нс/оп | ~156 нс/оп | `TreapDictionary` в **1,03×** быстрее |

---

**Анализ результатов:**

*Инициализация.* Обе реализации уступают `std::map` по скорости построения структуры. `SkipListDictionary` медленнее примерно в 1,85×, поскольку каждая вставка требует случайного выбора уровня нового узла и обновления массива указателей на нескольких уровнях списка. `TreapDictionary` уступает в 2,40×: помимо стандартного поиска позиции вставки по ключу выполняется поддержание свойства кучи по приоритетам, что приводит к дополнительным поворотам дерева и увеличивает константные накладные расходы.

*Чтение.* Для операций поиска результаты различаются. `SkipListDictionary` уступает `std::map` примерно в 1,7×. Несмотря на асимптотическую сложность $O(\log n)$, поиск в skip-list сопровождается большим числом переходов по указателям между уровнями, что ухудшает локальность данных и увеличивает число обращений к памяти. Напротив, `TreapDictionary` демонстрирует небольшое преимущество над `std::map` (около 1,09×). Обе структуры имеют логарифмическую высоту, однако случайная форма декартова дерева в данном эксперименте обеспечила несколько меньшее среднее число сравнений при поиске.

*ContainsKey.* Картина аналогична операции чтения. `SkipListDictionary` уступает `std::map` примерно в 1,66× по тем же причинам, связанным с многоуровневым обходом структуры. `TreapDictionary` показывает результат, близкий к эталонному, однако остаётся медленнее примерно в 1,25×, что объясняется дополнительными переходами между узлами и менее предсказуемой структурой дерева.

*Итерация.* Обе альтернативные реализации демонстрируют небольшое преимущество над `std::map`. Для `SkipListDictionary` выигрыш составляет около 1,06×, поскольку последовательный обход нижнего уровня списка фактически сводится к линейному проходу по связному списку без необходимости поиска следующего элемента. `TreapDictionary` также показывает преимущество (около 1,03×), что связано с эффективной реализацией итератора и относительно небольшими накладными расходами при переходе между соседними узлами.

*Общий вывод.* `SkipListDictionary` обеспечивает простую вероятностно-сбалансированную структуру данных с логарифмической асимптотикой операций, однако уступает `std::map` по большинству измеренных показателей из-за значительных константных накладных расходов. `TreapDictionary` демонстрирует более конкурентоспособные результаты: несмотря на более медленное построение, структура показывает производительность поиска, сопоставимую со `std::map`, а также небольшое преимущество при итерации. Таким образом, декартово дерево является наиболее близкой альтернативой стандартной реализации среди рассмотренных структур, тогда как skip-list может представлять интерес благодаря простоте реализации и вероятностной балансировке.
