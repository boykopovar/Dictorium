## ГЛАВА 1. ХЭШ-ТАБЛИЦЫ

### 1.1 Введение в хэш-таблицы

Многие практические приложения, такие как компиляторы, системы управления базами данных или сетевые маршрутизаторы, требуют организации динамических множеств данных, поддерживающих базовый набор словарных операций: INSERT (вставка), SEARCH (поиск) и DELETE (удаление). В качестве примера можно привести таблицу символов компилятора, где ключами элементов выступают произвольные строки символов — идентификаторы языка программирования.

Простейшим подходом к реализации словаря является прямая адресация, эффективно использующая возможность доступа к произвольному элементу массива за время $O(1)$. Если множество всех возможных ключей $U$ невелико, можно выделить таблицу $T[0..m-1]$, где каждый слот (позиция) соответствует конкретному ключу $k \in U$. В этом случае операции реализуются тривиально: Insert помещает элемент $x$ в слот $T[x.key]$, Search возвращает значение $T[k]$, а Delete обнуляет слот $T[x.key]$.

**Процедура 1.1.1. Direct Address Search**
```
01: DirectAddressSearch(T, k)
02:     return T[k]
```

**Процедура 1.1.2. Direct Address Insert**
```
01: DirectAddressInsert(T, x)
02:     T[x.key] = x
```

**Процедура 1.1.3. Direct Address Delete**
```
01: DirectAddressDelete(T, x)
02:     T[x.key] = NIL
```

Однако данный метод обладает недостатком, делающим его неприменимым в большинстве реальных сценариев: объём выделяемой памяти на таблицу $T$ размера $|U|$ часто непрактичен или абсолютно невозможен, особенно когда множество фактически хранимых ключей $K$ ничтожно мало по сравнению с $U$, что приводит к нерациональному расходованию ресурсов.

Альтернативой прямой адресации, снимающей ограничение на размер $U$, выступает хеширование. Хеш-таблица предполагает использование массива размером $m$, пропорциональным числу реально хранимых ключей $|K|$, то есть $\Theta(|K|)$. Вместо использования самого ключа в качестве индекса, индекс слота вычисляется с помощью хеш-функции $h(k)$. Функция $h$ выполняет отображение множества всех возможных ключей $U$ во множество допустимых индексов таблицы:

$$h: U \to \{0, 1, \ldots, m-1\},$$

где $m \ll |U|$. Элемент с ключом $k$ помещается в слот $h(k)$, который называется хеш-значением ключа.

Поскольку мощность множества всех возможных ключей превышает размер таблицы ($|U| > m$), возможна ситуация, при которой два или более различных ключа отображаются в один и тот же слот. Такая ситуация называется коллизией. Хотя идеально спроектированная хеш-функция, обладающая свойствами равномерного и случайного распределения, способна минимизировать число коллизий, полностью исключить их при детерминированном характере $h(k)$ невозможно. Вследствие этого критически важной частью построения хеш-таблиц становятся методы разрешения коллизий. Далее в главе будут рассмотрены два фундаментальных подхода к разрешению коллизий: метод цепочек (открытое хеширование), предполагающий хранение коллидирующих элементов в виде связного списка для каждого слота, и метод открытой адресации, при котором все элементы хранятся непосредственно в массиве, а процедура вставки при возникновении коллизии исследует альтернативные слоты согласно определённой последовательности проб.

### 1.2 Хэш-функции

Хорошая хеш-функция удовлетворяет (приблизительно) предположению простого равномерного хеширования: каждый ключ с равной вероятностью хешируется в любой из $m$ слотов, независимо от того, в какой слот попали другие ключи. К сожалению, у нас обычно нет способа проверить это условие, поскольку мы редко знаем распределение вероятностей, из которого берутся ключи. Более того, ключи могут выбираться не независимо друг от друга.

Иногда мы всё же знаем распределение. Например, если известно, что ключи — это случайные вещественные числа $k$, независимо и равномерно распределённые в диапазоне $0 \le k < 1$, то хеш-функция $h(k) = \lfloor km \rfloor$ удовлетворяет условию простого равномерного хеширования.

Большинство хеш-функций предполагают, что множество ключей — это множество $\mathbb{N} = \{0, 1, 2, \ldots\}$ натуральных чисел. Таким образом, если ключи не являются натуральными числами, мы находим способ интерпретировать их как натуральные числа. Например, мы можем интерпретировать строку символов как целое число, выраженное в подходящей системе счисления. Так, мы можем интерпретировать идентификатор `pt` как пару десятичных целых чисел $(112, 116)$, поскольку `p = 112` и `t = 116` в наборе символов ASCII; тогда, выраженный как целое число по основанию 128, `pt` становится $(112 \cdot 128) + 116 = 14452$. В контексте конкретного приложения мы обычно можем разработать какой-либо подобный метод для интерпретации каждого ключа как натурального числа. В дальнейшем мы предполагаем, что ключи являются натуральными числами.

#### Метод деления

В методе деления для создания хеш-функций мы отображаем ключ $k$ в один из $m$ слотов, беря остаток от деления $k$ на $m$. То есть хеш-функция имеет вид

$$h(k) = k \bmod m.$$

Например, если хеш-таблица имеет размер $m = 12$, а ключ равен $k = 100$, то $h(k) = 4$. Поскольку требуется только одна операция деления, хеширование делением выполняется довольно быстро.

#### Метод умножения

Метод умножения для создания хеш-функций действует в два этапа. Сначала мы умножаем ключ $k$ на константу $A$ в диапазоне $0 < A < 1$ и извлекаем дробную часть $kA$. Затем мы умножаем это значение на $m$ и берём целую часть результата. Короче говоря, хеш-функция имеет вид

$$h(k) = \lfloor m(kA \bmod 1) \rfloor,$$

где «$kA \bmod 1$» означает дробную часть $kA$, то есть $kA - \lfloor kA \rfloor$. Преимущество метода умножения в том, что значение $m$ не критично. Хотя этот метод работает с любым значением константы $A$, с одними значениями он работает лучше, чем с другими. Оптимальный выбор зависит от характеристик хешируемых данных.

#### Универсальное хеширование

При универсальном хешировании в начале выполнения мы выбираем хеш-функцию случайным образом из тщательно разработанного класса функций. Рандомизация гарантирует, что ни один входной набор данных не будет всегда вызывать поведение в худшем случае. Поскольку мы выбираем хеш-функцию случайно, алгоритм может вести себя по-разному при каждом выполнении, даже для одних и тех же входных данных, гарантируя хорошую производительность в среднем для любых входных данных.

Пусть $\mathcal{H}$ — конечный набор хеш-функций, отображающих заданное множество ключей $U$ в множество $\{0, 1, \ldots, m-1\}$. Такой набор называется универсальным, если для каждой пары различных ключей $k, l \in U$ количество хеш-функций $h \in \mathcal{H}$, для которых $h(k) = h(l)$, не превышает $|\mathcal{H}|/m$. Другими словами, для хеш-функции, случайно выбранной из $\mathcal{H}$, вероятность коллизии между различными ключами $k$ и $l$ не превышает вероятности $1/m$ коллизии, если бы $h(k)$ и $h(l)$ были случайно и независимо выбраны из множества $\{0, 1, \ldots, m-1\}$.

### 1.3 Открытое хеширование

В рамках данной работы была разработана структура данных `ChainingHashDictionary<TKey, TValue, Hash>`, реализующая ассоциативный массив на основе хэш-таблицы с разрешением коллизий открытым хешированием.

Внутреннее представление структуры основано на использовании массива корзин, каждая из которых хранит список элементов, имеющих одинаковое хеш-значение.

В реализации для хранения корзин используется контейнер `std::vector<std::list<std::pair<TKey, TValue>>>`. Каждый элемент таблицы представляет собой пару: ключ (`TKey`), связанное значение (`TValue`). Вычисление индекса корзины происходит по методу деления: $h(k) = k \bmod m$. При возникновении коллизии элементы помещаются в одну цепочку соответствующей корзины. Метод `_getIndex` реализует вычисление индекса корзины по ключу и используется большинством операций структуры. Псевдокод процедуры вычисления индекса представлен ниже.

**Процедура 1.3.1. Get Index**
```
01: GetIndexImpl(key)
02:     return Hash(key) mod BucketCount
```

Анализ сложности:

$$n = |key| \text{ — длина ключа}$$

$$T(n) = T_{\text{Hash}}(n) + T_{\text{mod}} + T_{\text{return}}$$

$$T_{\text{Hash}}(n) = an + b, \quad a = \text{const},\ b = \text{const}$$

$$T_{\text{mod}} = \text{const}, \quad T_{\text{return}} = \text{const}$$

$$T(n) = an + d, \quad a > 0,\ d \ge 0$$

$$c_1 n \le T(n) \le c_2 n$$

$$an \le an + d \le (a+d)n, \quad \forall n \ge 1$$

$$\exists c_1, c_2 > 0,\ \exists n_0 \in \mathbb{N}:\ \forall n \ge n_0 \quad c_1 n \le T(n) \le c_2 n \Rightarrow T(n) \in \Theta(n)$$

Пусть $X_n = \{x : |x| = n\}$ — множество всех ключей размера $n$, $T: X \to \mathbb{N}$, $T(x)$ — число элементарных операций алгоритма на входе $x$.

$$T(x) = a|x| + d \text{ — не зависит от конкретного } x$$

$$\Rightarrow W(n) = A(n) = B(n) = \Theta(n)$$

---

Метод `_ensureCapacity` предназначен для контроля коэффициента загрузки таблицы. После выполнения операций вставки осуществляется проверка отношения количества элементов к числу корзин. При превышении допустимого значения вызывается процедура `_rehash`, выполняющая увеличение размера таблицы и повторное распределение элементов между новыми корзинами.

**Процедура 1.3.2. Ensure Capacity**
```
01: EnsureCapacityImpl()
02:     if Count / BucketCount > MaxLoadFactor then
03:         RehashImpl()
```

Анализ сложности:

$$n = \text{Count} \text{ — количество элементов в хеш-таблице}$$

$$m = \text{BucketCount} \text{ — количество корзин}$$

$$\alpha = \frac{n}{m} \text{ — текущий коэффициент загрузки}$$

$$\alpha_{\max} = \text{MaxLoadFactor} = \text{const} > 0$$

$$T(n) = T_{\text{проверка}} + T_{\text{условие}} + T_{\text{вызов}}$$

$$T_{\text{проверка}} = c_1 = \text{const}, \quad T_{\text{условие}} = c_2 = \text{const}$$

$$T_{\text{вызов}} = \begin{cases} T_{\text{Rehash}}(n), & \alpha > \alpha_{\max} \\ 0, & \alpha \le \alpha_{\max} \end{cases}$$

**Случай 1:** $\alpha \le \alpha_{\max}$

$$T(n) = c_1 + c_2 = c_3 = \text{const} \Rightarrow T(n) \in \Theta(1)$$

**Случай 2:** $\alpha > \alpha_{\max}$

По процедуре 1.3.3: $T_{\text{Rehash}}(n) = an + d,\ a > 0,\ d \ge 0$

$$T(n) = c_1 + c_2 + (an + d) = an + d'$$

$$an \le an + d' \le (a + d')n, \quad \forall n \ge 1 \Rightarrow T(n) \in \Theta(n)$$

Пусть $X_n = \{x : |x| = n\}$ — множество всех состояний хеш-таблицы, содержащих ровно $n$ элементов.

$$T(x) = \begin{cases} c_3, & \alpha > \alpha_{\max} \\ an + d', & \alpha \le \alpha_{\max} \end{cases}$$

$$B(n) = \min_{x \in X_n} T(x) = c_3 \quad \text{(можно подобрать } m \text{ достаточно большим, чтобы } \alpha > \alpha_{\max}\text{)}$$

$$W(n) = \max_{x \in X_n} T(x) = an + d' \quad \text{(можно подобрать } m \text{ достаточно малым, чтобы } \alpha \le \alpha_{\max}\text{)}$$

$$A(n) = \frac{1}{n} \sum_{i=1}^{n} T_i = \frac{\Theta(n)}{n} = \Theta(1)$$

---

Процедура `_rehash` создаёт новый массив корзин увеличенного размера, после чего каждый элемент существующей таблицы повторно проходит процедуру вычисления индекса относительно нового размера массива.

**Процедура 1.3.3. Rehash**
```
01: RehashImpl()
02:     newSize = BucketCount * 2
03:     newBuckets = array[newSize]
04:
05:     for each bucket in Buckets do
06:         for each (key, value) in bucket do
07:             index = Hash(key) mod newSize
08:             newBuckets[index].append((key, value))
09:
10:     Buckets = newBuckets
```

Анализ сложности:

$$n \text{ — количество элементов до рехеширования}$$

$$m = \text{BucketCount} \text{ — количество корзин до рехеширования}$$

$$m' = 2m \text{ — количество корзин после рехеширования}$$

$$\alpha = \frac{n}{m} = \Theta(1) \Rightarrow m = \Theta(n)$$

$$T(n) = T_{\text{newSize}} + T_{\text{newBuckets}} + T_{\text{loops}} + T_{\text{assign}}$$

$$T_{\text{newSize}} = c_1 = \text{const}$$

$$T_{\text{newBuckets}} = c_2 \cdot m' = c_2 \cdot 2m = c_2' m, \quad c_2' = 2c_2 = \text{const}$$

$$m = kn,\ k > 0 \Rightarrow T_{\text{newBuckets}} = c_2' \cdot kn = c_2'' n, \quad c_2'' = \text{const}$$

$$T_{\text{elem}} = T_{\text{Hash}} + T_{\text{mod}} + T_{\text{append}}$$

По процедуре 1.3.1: $T_{\text{Hash}}(key) = a|key| + b$, но для фиксированного вызова Rehash длины ключей не меняются, поэтому:

$$T_{\text{Hash}} = a' = \text{const}, \quad T_{\text{mod}} = c_3 = \text{const}, \quad T_{\text{append}} = c_4 = \text{const}$$

$$T_{\text{elem}} = c_5 = \text{const}$$

$$T_{\text{loops}} = \sum_{i=1}^{n} c_5 = c_5 n$$

$$T_{\text{assign}} = c_6 = \text{const}$$

$$T(n) = c_1 + c_2'' n + c_5 n + c_6$$

Пусть $a = c_2'' + c_5 > 0,\ d = c_1 + c_6 \ge 0 \Rightarrow T(n) = an + d$

$$an \le an + d \le (a+d)n, \quad \forall n \ge 1$$

$$\exists c_{11}, c_{22} > 0,\ \exists n_0 \in \mathbb{N}:\ \forall n \ge n_0 \quad c_{11} n \le T(n) \le c_{22} n \Rightarrow T(n) \in \Theta(n)$$

$$\Rightarrow W(n) = A(n) = B(n) = \Theta(n)$$

Операции поиска реализованы методами `ContainsKey`, `GetValue` и `TryGetValue`. Все перечисленные методы используют одинаковый принцип работы: после вычисления индекса корзины выполняется последовательный просмотр элементов соответствующей цепочки. Метод `ContainsKey` возвращает логическое значение, отражающее факт наличия ключа в таблице.

**Процедура 1.3.4. Contains Key**
```
01: ContainsKeyImpl(key)
02:     index = GetIndexImpl(key)
03:     bucket = Buckets[index]
04:
05:     for each (k, v) in bucket do
06:         if k = key then
07:             return true
08:
09:     return false
```

- **Входные данные:** `key` — ключ, наличие которого проверяется в таблице.

**Шаги алгоритма:**
1. Вычисляется индекс корзины: `index = GetIndexImpl(key)` — $\Theta(|key|)$.
2. Выполняется линейный перебор элементов цепочки `Buckets[index]`.
3. Если найден элемент с совпадающим ключом — возвращается `true`, иначе — `false`.

**Анализ сложности:**

*Худший случай* — все $n$ элементов таблицы попадают в одну корзину (например, все ключи дают одинаковое хеш-значение), а искомый ключ отсутствует либо находится в конце цепочки. Тогда перебор проходит все $n$ элементов:

$$W(n) = \Theta(n)$$

*Лучший случай* — искомый ключ находится первым в цепочке, либо цепочка содержит один элемент. Перебор завершается после первого сравнения:

$$B(n) = \Theta(1)$$

*Амортизированный случай* — операция `ContainsKey` является read-only и не изменяет состояние таблицы, поэтому её стоимость не перераспределяется между вызовами. Амортизированная сложность совпадает с худшим случаем:

$$A(n) = W(n) = \Theta(n)$$

---

Метод `TryGetValue` дополнительно записывает найденное значение в выходной параметр и возвращает результат успешности поиска.

**Процедура 1.3.5. Try Get Value**
```
01: TryGetValueImpl(key, value)
02:     index = GetIndexImpl(key)
03:     bucket = Buckets[index]
04:
05:     for each (k, v) in bucket do
06:         if k = key then
07:             value = v
08:             return true
09:
10:     return false
```

- **Входные данные:** `key` — искомый ключ; `value` — выходной параметр, в который записывается найденное значение.

**Шаги алгоритма:**
1. Вычисляется индекс корзины: `index = GetIndexImpl(key)`.
2. Выполняется линейный перебор элементов цепочки `Buckets[index]`.
3. При совпадении ключа — значение записывается в `value`, возвращается `true`.
4. Если ключ не найден — возвращается `false`.

**Анализ сложности:**

*Худший случай* — все $n$ элементов в одной корзине, ключ отсутствует или находится в конце цепочки:

$$W(n) = \Theta(n)$$

*Лучший случай* — ключ является первым элементом цепочки:

$$B(n) = \Theta(1)$$

*Амортизированный случай* — операция является read-only, стоимость не перераспределяется между вызовами:

$$A(n) = W(n) = \Theta(n)$$

Метод `GetValue` возвращает ссылку на найденное значение, а при отсутствии ключа генерирует исключение.

**Процедура 1.3.6. Get Value**
```
01: GetValueImpl(key)
02:     index = GetIndexImpl(key)
03:     bucket = Buckets[index]
04:
05:     for each (k, v) in bucket do
06:         if k = key then
07:             return v
08:
09:     raise KeyNotFoundException
```

- **Входные данные:** `key` — искомый ключ.

**Шаги алгоритма:**
1. Вычисляется индекс корзины: `index = GetIndexImpl(key)`.
2. Выполняется линейный перебор элементов цепочки.
3. При совпадении ключа — возвращается ссылка на значение `v`.
4. Если ключ не найден — генерируется исключение `KeyNotFoundException`.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = \Theta(1), \quad A(n) = W(n) = \Theta(n)$$

Операция вставки реализована методами `Add` и `InsertOrAssign`. Метод `Add` выполняет добавление нового элемента только при условии отсутствия ключа в таблице. Перед вставкой осуществляется последовательный просмотр цепочки соответствующей корзины. Если ключ уже существует, генерируется исключение `DuplicateKeyException`. В противном случае новый элемент добавляется в конец списка корзины, после чего увеличивается счётчик элементов таблицы и выполняется проверка необходимости рехэширования.

**Процедура 1.3.7. Add**
```
01: AddImpl(key, value)
02:     index = GetIndexImpl(key)
03:     bucket = Buckets[index]
04:     for each (k, v) in bucket do
05:         if k = key then
06:             raise DuplicateKeyException
07:     bucket.append((key, value))
08:     Count = Count + 1
09:
10:     EnsureCapacityImpl()
```

- **Входные данные:** `key` — ключ; `value` — значение.

**Шаги алгоритма:**
1. Вычисляется индекс корзины: `index = GetIndexImpl(key)`.
2. Выполняется линейный перебор цепочки: если ключ уже существует — генерируется `DuplicateKeyException`.
3. Новый элемент добавляется в конец цепочки, счётчик увеличивается.
4. Вызывается `EnsureCapacityImpl` — при превышении коэффициента загрузки производится рехеширование.

**Анализ сложности:**

*Худший случай* — все $n$ элементов в одной корзине, ключ в конце или вызывается рехеширование:

$$W(n) = \Theta(n)$$

*Лучший случай* — корзина пуста, рехеширование не требуется:

$$B(n) = \Theta(1)$$

*Амортизированный случай* — стоимость рехеширования равномерно распределяется на все вставки (каждый элемент рехешируется $O(\log n)$ раз), поэтому амортизированная стоимость одной вставки:

$$A(n) = \Theta(1)$$

Метод `InsertOrAssign` реализует комбинированную операцию обновления либо вставки. Если ключ найден, соответствующее значение обновляется без изменения структуры таблицы. Если ключ отсутствует, выполняется добавление нового элемента.

**Процедура 1.3.8. Insert Or Assign**
```
01: InsertOrAssignImpl(key, value)
```

4. Вызывается `EnsureCapacityImpl`.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = \Theta(1), \quad A(n) = \Theta(1)$$

Удаление элементов реализовано методом `Remove`. После вычисления индекса корзины выполняется последовательный просмотр элементов цепочки. При обнаружении элемента с указанным ключом выполняется его удаление из списка корзины, после чего уменьшается счётчик элементов таблицы и возвращается признак успешного удаления.

### 1.4 Открытая адресация. Линейное пробирование

В рамках данной работы была разработана структура данных `LinearProbingDictionary<TKey, TValue, Hash>`, реализующая ассоциативный массив на основе хэш-таблицы с открытой адресацией и линейным пробированием.

При открытой адресации все элементы хранятся непосредственно в массиве таблицы. При возникновении коллизии выполняется последовательный просмотр (пробирование) следующих слотов. При линейном пробировании смещение составляет фиксированный шаг, равный 1. Удаление элементов реализовано с использованием tombstone-маркеров: удалённый слот помечается состоянием `Deleted` и при последующем поиске не прерывает цепочку проб.

Каждый слот таблицы хранит объект типа `Entry`, включающий ключ, значение и одно из трёх состояний: `Empty` (никогда не использовался), `Occupied` (содержит элемент) или `Deleted` (помечен как удалённый). Максимальный коэффициент загрузки $\alpha_{\max} = 0{,}75$. Вычисление начального индекса выполняется по методу деления: $h(k) = k \bmod m$, где $m$ — текущая ёмкость таблицы. Последовательность проб при линейном пробировании:

$$pos_i = (h(key) + i) \bmod m, \quad i = 0, 1, 2, \ldots$$

**Процедура 1.4.1. Find Index**
```
01: FindIndex(key)
02:     capacity = Table.size
03:     index = Hash(key) mod capacity
04:
05:     for i from 0 to capacity - 1 do
06:         pos = (index + i) mod capacity
07:
08:         if Table[pos].state = Empty then
09:             return capacity
10:
11:         if Table[pos].state = Occupied and Table[pos].key = key then
12:             return pos
13:
14:     return capacity
```

- **Входные данные:** `key` — искомый ключ.

**Шаги алгоритма:**
1. Вычисляется начальный индекс `index = Hash(key) mod capacity`.
2. Выполняется последовательный перебор слотов: `pos = (index + i) mod capacity`.
3. Если слот пуст (`Empty`) — поиск завершается неудачей, возвращается `capacity` (признак отсутствия).
4. Если слот занят (`Occupied`) и ключ совпадает — возвращается позиция `pos`.
5. Слоты со статусом `Deleted` пропускаются, цепочка продолжается.

**Анализ сложности:**

*Худший случай* — все $n$ элементов расположены в одной цепочке проб (все ключи дают одинаковый начальный индекс), искомый ключ отсутствует или находится в конце:

$$W(n) = \Theta(n)$$

*Лучший случай* — ключ находится в слоте с начальным индексом (первая проба успешна):

$$B(n) = \Theta(1)$$

*Средний случай* — при равномерном распределении ключей и коэффициенте загрузки $\alpha < 1$ среднее число проб равно $\frac{1}{1-\alpha}$:

$$A(n) = \Theta(1) \quad (\text{при } \alpha \le \alpha_{\max} = \text{const} < 1)$$

---

**Процедура 1.4.2. Find Slot For Insert**
```
01: FindSlotForInsert(key)
02:     capacity = Table.size
03:     index = Hash(key) mod capacity
04:     firstDeleted = capacity
05:
06:     for i from 0 to capacity - 1 do
07:         pos = (index + i) mod capacity
08:
09:         if Table[pos].state = Occupied and Table[pos].key = key then
10:             return pos
11:
12:         if Table[pos].state = Deleted and firstDeleted = capacity then
13:             firstDeleted = pos
14:
15:         if Table[pos].state = Empty then
16:             if firstDeleted ≠ capacity then return firstDeleted
17:             return pos
18:
19:     return capacity
```

- **Входные данные:** `key` — ключ, для которого ищется слот вставки.

**Шаги алгоритма:**
1. Вычисляется начальный индекс `index = Hash(key) mod capacity`.
2. Запоминается позиция первого встреченного слота `Deleted` в `firstDeleted`.
3. Если найден `Occupied`-слот с совпадающим ключом — возвращается его позиция (для обновления значения).
4. Если найден `Empty`-слот — возвращается `firstDeleted` (если был встречен), иначе — текущая позиция.
5. Повторное использование `Deleted`-слотов предотвращает деградацию при частых вставках и удалениях.

**Анализ сложности:**

*Худший случай* — все $n$ слотов заняты или помечены как удалённые, поиск требует полного обхода:

$$W(n) = \Theta(n)$$

*Лучший случай* — первый слот по начальному индексу свободен:

$$B(n) = \Theta(1)$$

*Средний случай* — аналогично `FindIndex` при $\alpha \le \alpha_{\max}$:

$$A(n) = \Theta(1)$$

---

**Процедура 1.4.3. Ensure Capacity**
```
01: EnsureCapacityImpl()
02:     if Count / Table.size > MaxLoadFactor then
03:         RehashImpl()
```

- **Входные данные:** нет явных аргументов; используются внутренние поля `Count` и `Table.size`.

**Шаги алгоритма:**
1. Вычисляется текущий коэффициент загрузки $\alpha = n / m$.
2. Если $\alpha > \alpha_{\max} = 0{,}75$ — вызывается процедура рехеширования.

**Анализ сложности:**

*Худший случай* ($\alpha > \alpha_{\max}$, вызывается `Rehash`):

$$W(n) = \Theta(n)$$

*Лучший и средний случай* ($\alpha \le \alpha_{\max}$, `Rehash` не вызывается):

$$B(n) = A(n) = \Theta(1)$$

---

**Процедура 1.4.4. Rehash**
```
01: RehashImpl()
02:     old = Table
03:     Table = new array[Table.size * 2]
04:     Count = 0
05:
06:     for each entry in old do
07:         if entry.state = Occupied then
08:             InsertOrAssign(entry.key, entry.value)
```

- **Входные данные:** нет явных аргументов; выполняется над внутренними структурами таблицы.

**Шаги алгоритма:**
1. Сохраняется старый массив в `old`.
2. Создаётся новый массив удвоенного размера.
3. Счётчик элементов обнуляется.
4. Каждый `Occupied`-элемент старой таблицы повторно вставляется в новую.

**Анализ сложности:**

Все $n$ занятых элементов перевставляются; каждая вставка выполняется за $\Theta(1)$ при $\alpha \le \alpha_{\max}$:

$$W(n) = B(n) = A(n) = \Theta(n)$$

**Процедура 1.4.5. Contains Key**

**Процедура 1.4.12. Count**

### 1.5 Открытая адресация. Квадратичное пробирование

В рамках данной работы была разработана структура данных `QuadraticProbingDictionary<TKey, TValue, Hash>`, реализующая ассоциативный массив на основе хэш-таблицы с открытой адресацией и квадратичным пробированием.

Квадратичное пробирование снижает первичную кластеризацию, характерную для линейного пробирования: шаг между пробами увеличивается квадратично, что рассеивает элементы по таблице. Однако элементы с одинаковым начальным индексом по-прежнему проходят одну и ту же последовательность проб (вторичная кластеризация). Последовательность проб:

$$pos_i = (h(key) + i + i^2) \bmod m, \quad i = 0, 1, 2, \ldots$$

Гарантия нахождения свободного слота обеспечивается при простом размере таблицы и коэффициенте загрузки $\alpha \le 0{,}5$. Для поддержания простого размера реализованы вспомогательные методы `_isPrime` и `_nextPrime`. Удаление реализовано через tombstone-маркеры аналогично линейному пробированию.

**Процедура 1.5.1. Is Prime**
```
01: IsPrime(n)
02:     if n < 2 then return false
03:     for i from 2 to floor(sqrt(n)) do
04:         if n mod i = 0 then return false
05:     return true
```

- **Входные данные:** `n` — натуральное число для проверки на простоту.

**Шаги алгоритма:**
1. Если $n < 2$ — возвращается `false`.
2. Перебираются потенциальные делители от 2 до $\lfloor\sqrt{n}\rfloor$.
3. Если найден делитель — возвращается `false`, иначе — `true`.

**Анализ сложности:**

$$W(n) = B(n) = A(n) = \Theta(\sqrt{n})$$

---

**Процедура 1.5.2. Next Prime**
```
01: NextPrime(n)
02:     if n ≤ 2 then return 2
03:     if n mod 2 = 0 then n = n + 1
04:     while true do
05:         isPrime = true
06:         for i from 3 to floor(sqrt(n)) step 2 do
07:             if n mod i = 0 then isPrime = false; break
08:         if isPrime then return n
09:         n = n + 2
```

- **Входные данные:** `n` — нижняя граница для искомого простого числа.

**Шаги алгоритма:**
1. Если $n \le 2$ — возвращается 2.
2. Выравнивается до нечётного числа (если чётное).
3. Перебираются нечётные числа, начиная с `n`, до нахождения простого.

**Анализ сложности:**

По теореме о простых числах расстояние между соседними простыми числами вблизи $n$ составляет $O(\ln n)$, откуда:

$$W(n) = B(n) = A(n) = O(\sqrt{n} \ln n)$$

---

**Процедура 1.5.3. Find Index**
```
01: FindIndex(key)
02:     capacity = Table.size
03:     index = Hash(key) mod capacity
04:
05:     for i from 0 to capacity - 1 do
06:         pos = (index + i + i * i) mod capacity
07:
08:         if Table[pos].state = Empty then return capacity
09:         if Table[pos].state = Occupied and Table[pos].key = key then return pos
10:
11:     return capacity
```

- **Входные данные:** `key` — искомый ключ.

**Шаги алгоритма:**
1. Вычисляется начальный индекс `index`.
2. Последовательность проб: `pos = (index + i + i²) mod capacity`.
3. При обнаружении `Empty` — поиск завершается неудачей.
4. При совпадении ключа в `Occupied`-слоте — возвращается позиция.
5. `Deleted`-слоты пропускаются, цепочка проб продолжается.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = \Theta(1), \quad A(n) = \Theta(1)$$

---

**Процедура 1.5.4. Find Slot For Insert**
```
01: FindSlotForInsert(key)
02:     capacity = Table.size
03:     index = Hash(key) mod capacity
04:     firstDeleted = capacity
05:
06:     for i from 0 to capacity - 1 do
07:         pos = (index + i + i * i) mod capacity
08:
09:         if Table[pos].state = Occupied and Table[pos].key = key then return pos
10:
11:         if Table[pos].state = Deleted and firstDeleted = capacity then
12:             firstDeleted = pos
13:
14:         if Table[pos].state = Empty then
15:             if firstDeleted ≠ capacity then return firstDeleted
16:             return pos
17:
18:     return capacity
```

- **Входные данные:** `key` — ключ, для которого ищется слот.

**Шаги алгоритма:**
1. Применяется та же квадратичная последовательность проб.
2. Запоминается первый встреченный `Deleted`-слот.
3. Возвращается первый пригодный слот: ранее удалённый или пустой.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = \Theta(1), \quad A(n) = \Theta(1)$$

**Процедура 1.5.5. Ensure Capacity**
```

```

- **Входные данные:** нет явных аргументов.

**Шаги алгоритма:**

2. При $\alpha > \alpha_{\max} = 0{,}5$ — вызывается рехеширование. Пороговое значение 0,5 гарантирует нахождение свободного слота при квадратичном пробировании с простым размером таблицы.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = A(n) = \Theta(1)$$

### 1.6 Открытая адресация. Двойное хеширование

В рамках данной работы была разработана структура данных `DoubleHashDictionary<TKey, TValue, Hash1, Hash2>`, реализующая ассоциативный массив на основе хэш-таблицы с открытой адресацией и двойным хешированием.

При двойном хешировании шаг пробирования вычисляется второй хеш-функцией, что устраняет вторичную кластеризацию, присущую квадратичному пробированию. Последовательность проб:

$$pos_i = (h_1(key) + i \cdot h_2(key)) \bmod m, \quad i = 0, 1, 2, \ldots$$

где $h_1(key) = \text{Hash1}(key) \bmod m$ — первичный хеш, задающий начальный слот; $h_2(key) = 1 + (\text{Hash2}(key) \bmod (m-1))$ — вторичный хеш, определяющий шаг (никогда не равен нулю). Размер таблицы всегда простой, что при указанных условиях гарантирует $\gcd(h_2, m) = 1$ и, следовательно, полный обход всех слотов. Максимальный коэффициент загрузки $\alpha_{\max} = 0{,}75$. Удаление реализовано через tombstone-маркеры. Вспомогательные функции `_isPrime` и `_nextPrime` аналогичны процедурам 1.5.1 и 1.5.2.

**Процедура 1.6.1. Hash1**
```
01: Hash1(key)
02:     return Hasher1(key) mod Table.size
```

- **Входные данные:** `key` — ключ.

**Шаги алгоритма:**
1. Вычисляется хеш-значение ключа с помощью `Hasher1`.
2. Возвращается остаток от деления на `Table.size`.

**Анализ сложности:**

$$W(n) = B(n) = A(n) = \Theta(|key|)$$

---

**Процедура 1.6.2. Hash2**
```
01: Hash2(key)
02:     return 1 + (Hasher2(key) mod (Table.size - 1))
```

- **Входные данные:** `key` — ключ.

**Шаги алгоритма:**
1. Вычисляется хеш-значение ключа с помощью `Hasher2`.
2. Берётся остаток от деления на $(m - 1)$ и прибавляется 1.
3. Результат всегда в диапазоне $[1,\, m-1]$, что исключает зацикливание пробирования.

**Анализ сложности:**

$$W(n) = B(n) = A(n) = \Theta(|key|)$$

---

**Процедура 1.6.3. Find Index**
```
01: FindIndex(key)
02:     capacity = Table.size
03:     h1 = Hash1(key)
04:     h2 = Hash2(key)
05:
06:     for i from 0 to capacity - 1 do
07:         pos = (h1 + i * h2) mod capacity
08:
09:         if Table[pos].state = Empty then return capacity
10:         if Table[pos].state = Occupied and Table[pos].key = key then return pos
11:
12:     return capacity
```

- **Входные данные:** `key` — искомый ключ.

**Шаги алгоритма:**
1. Вычисляются оба хеша: `h1`, `h2`.
2. Последовательность проб: `pos = (h1 + i * h2) mod capacity`.
3. Пустой слот означает отсутствие ключа.
4. Занятый слот с совпадающим ключом — возврат позиции.
5. `Deleted`-слоты пропускаются.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = \Theta(1), \quad A(n) = \Theta(1)$$

---

**Процедура 1.6.4. Find Slot For Insert**
```
01: FindSlotForInsert(key)
02:     capacity = Table.size
03:     h1 = Hash1(key)
04:     h2 = Hash2(key)
05:     firstDeleted = capacity
06:
07:     for i from 0 to capacity - 1 do
08:         pos = (h1 + i * h2) mod capacity
09:
10:         if Table[pos].state = Occupied and Table[pos].key = key then return pos
11:
12:         if Table[pos].state = Deleted and firstDeleted = capacity then
13:             firstDeleted = pos
14:
15:         if Table[pos].state = Empty then
16:             if firstDeleted ≠ capacity then return firstDeleted
17:             return pos
18:
19:     return capacity
```

- **Входные данные:** `key` — ключ, для которого ищется слот.

**Шаги алгоритма:**
1. Применяется последовательность проб с шагом `h2`.
2. Запоминается первый встреченный `Deleted`-слот для повторного использования.
3. Возвращается первый пригодный слот.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = \Theta(1), \quad A(n) = \Theta(1)$$

---

**Процедура 1.6.5. Ensure Capacity**
```
01: EnsureCapacityImpl()
02:     if Count / Table.size > MaxLoadFactor then
03:         RehashImpl()
```

- **Входные данные:** нет явных аргументов.

**Шаги алгоритма:**
1. Вычисляется $\alpha = n / m$.
2. При $\alpha > 0{,}75$ — вызывается рехеширование.

**Анализ сложности:**

$$W(n) = \Theta(n), \quad B(n) = A(n) = \Theta(1)$$

---

**Процедура 1.6.6. Rehash**
```
01: RehashImpl()
02:     old = Table
03:     Table = new array[NextPrime(Table.size * 2)]
04:     Count = 0
05:
06:     for each entry in old do
07:         if entry.state = Occupied then
08:             InsertOrAssign(entry.key, entry.value)
```

- **Входные данные:** нет явных аргументов.

**Шаги алгоритма:**
1. Сохраняется старый массив.
2. Новый размер — следующее простое число $\ge 2m$: сохраняется простота размера таблицы, необходимая для гарантии полного покрытия при двойном хешировании.

### 1.7 Открытая адресация. Хеширование Робина Гуда

В рамках данной работы была разработана структура данных `RobinHoodHashDictionary<TKey, TValue, Hash>`, реализующая ассоциативный массив на основе хэш-таблицы с открытой адресацией и алгоритмом Robin Hood Hashing.

Ключевая идея алгоритма: при вставке нового элемента, если текущий слот уже занят элементом с **меньшим** PSL (Probe Sequence Length — длина пути пробирования от идеальной позиции до текущего слота), записи меняются местами. Вставляемый элемент как бы «отнимает» слот у «богатого» (хорошо расположенного) элемента в пользу «бедного» (далеко ушедшего от идеальной позиции). Это выравнивает распределение PSL по таблице и снижает дисперсию времени поиска.

Удаление реализуется без tombstone-маркеров методом **backward shift deletion**: после удаления элемента цепочка уплотняется — соседние элементы с $\text{PSL} > 0$ сдвигаются назад до тех пор, пока не встретится пустой слот или элемент с $\text{PSL} = 0$.

Каждая запись `Entry` содержит ключ, значение, флаг `occupied` и значение `psl`. Максимальный коэффициент загрузки $\alpha_{\max} = 0{,}75$.

**Процедура 1.7.1. Find Index**
```
01: FindIndex(key)
02:     capacity = Table.size
03:     index = Hash(key) mod capacity
04:     psl = 0
05:
06:     while true do
07:         entry = Table[index]
08:
09:         if not entry.occupied then return capacity
10:         if entry.psl < psl then return capacity
11:         if entry.key = key then return index
12:
13:         index = (index + 1) mod capacity
14:         psl = psl + 1
```

- **Входные данные:** `key` — искомый ключ.

**Шаги алгоритма:**
1. Вычисляется начальный индекс; инициализируется `psl = 0`.
2. Если слот пуст — ключ отсутствует в таблице.
3. Если PSL элемента в слоте меньше текущего `psl` — ключ не мог быть вставлен дальше (инвариант Robin Hood), поиск завершается неудачей.
4. Если ключ совпадает — возвращается позиция.
5. Иначе переход к следующему слоту, `psl` увеличивается.

**Анализ сложности:**

Инвариант ограниченного PSL обеспечивает ранний выход: поиск прекращается, как только PSL элемента слота меньше ожидаемого. Это снижает среднее число проб по сравнению с обычным линейным пробированием:

$$W(n) = \Theta(n), \quad B(n) = \Theta(1), \quad A(n) = \Theta(1)$$

```
01: InsertOrAssignImpl(key, value)
02:     EnsureCapacityImpl()
03:     current = Entry(key, value, occupied=true, psl=0)
04:     index = Hash(key) mod Table.size
05:
06:     while true do
07:         slot = Table[index]

09:         if not slot.occupied then
```
