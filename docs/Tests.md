# Universal Correctness Tests for IDictionary

Применимо ко всем наследникам `IDictionary<TKey, TValue>`.  
Тестируется на `TKey = int` и `TKey = std::string`, `TValue = double`.  
Эталон - `std::unordered_map<TKey, double>`.  
Размер входных данных: 10 000 уникальных пар, ключи генерируются случайно.

**Покрытие:** 15 тестов * 2 типа ключа * 10 структур = **300 проверок**.

---

## Метод доказательства корректности

Для каждой операции результат реализации сравнивается с результатом `std::unordered_map` на идентичных входных данных. Ожидается совпадение на случайных данных при всех тестовых сценариях на двух типах ключа.

---

## Тесты

### 1. Count after construction
`Count()` после построения из диапазона итераторов.  
**Доказывает:** конструктор вставил ровно столько элементов, сколько было во входных данных.  
**Проверка:** `dict.Count() == ref.size()`.

---

### 2. ContainsKey - все вставленные ключи присутствуют
`ContainsKey(k)` для каждого ключа из входных данных.  
**Доказывает:** ни один вставленный ключ не потерян.  
**Проверка:** `ContainsKey(k) == true` для всех `k` из входного набора.

---

### 3. TryGetValue - значения совпадают с эталоном
`TryGetValue(k, got)` для каждого ключа.  
**Доказывает:** (1) ключ находится, (2) возвращаемое значение совпадает с `unordered_map`.  
**Проверка:** возвращает `true` и `got == ref[k]` для всех `k`.

---

### 4. GetValue - значения совпадают с эталоном
`GetValue(k)` для каждого ключа.  
**Доказывает:** то же, что тест 3, через прямой доступ без out-параметра.  
**Проверка:** `dict.GetValue(k) == ref[k]` для всех `k`, исключений нет.

---

### 5. InsertOrAssign - обновление существующих ключей
`InsertOrAssign(k, v * 3.7 + 1.0)` для всех ключей, затем проверка значений и Count.  
**Доказывает:** (1) значения обновляются корректно, (2) новые записи не создаются - Count не меняется.  
**Проверка:** `dict.GetValue(k) == ref[k]` для всех `k`; `dict.Count() == ref.size()`.

---

### 6. Add duplicate - исключение на дубликате
`Add(k, v)` для уже существующего ключа.  
**Доказывает:** реализация соблюдает контракт `IDictionary` - дубликат запрещён.  
**Проверка:** бросает `std::invalid_argument`; любое другое исключение или отсутствие исключения - FAIL.

---

### 7. Remove - существующие ключи, корректность Count
`Remove(k)` для первой половины ключей, синхронно с `ref.erase(k)`.  
**Доказывает:** (1) Remove возвращает `true` для существующих ключей, (2) Count уменьшается на правильное число.  
**Проверка:** `Remove(k) == true`; `dict.Count() == ref.size()` после всех удалений.

---

### 8. ContainsKey - удалённые ключи отсутствуют
`ContainsKey(k)` для ключей из первой половины после их удаления.  
**Доказывает:** удалённые ключи недоступны для поиска.  
**Проверка:** `ContainsKey(k) == false` для всех удалённых `k`.

---

### 9. ContainsKey - неудалённые ключи остаются
`ContainsKey(k)` для второй половины (невидалённых) ключей.  
**Доказывает:** Remove не затрагивает посторонние элементы.  
**Проверка:** `ContainsKey(k) == true` для всех `k` из второй половины.

---

### 10. Remove - повторное удаление возвращает false
`Remove(k)` для уже удалённых ключей.  
**Доказывает:** Remove корректно сигнализирует об отсутствии элемента.  
**Проверка:** `Remove(k) == false` для всех ключей из первой половины.

---

### 11. TryGetValue - удалённые ключи не находятся
`TryGetValue(k, got)` для удалённых ключей.  
**Доказывает:** после Remove поиск по значению также не находит элемент.  
**Проверка:** `TryGetValue(k, got) == false` для всех удалённых `k`.

---

### 12. GetValue - выжившие ключи совпадают с эталоном
`GetValue(k)` для второй половины (невыдалённых) ключей после частичного удаления.  
**Доказывает:** значения оставшихся элементов не повреждены операциями Remove.  
**Проверка:** `dict.GetValue(k) == ref[k]` для всех `k` из второй половины.

---

### 13. Clear - Count равен нулю, все ключи отсутствуют
`Clear()`, затем проверка Count и ContainsKey для всего входного набора.  
**Доказывает:** словарь полностью очищён, структура остаётся валидной для дальнейших операций.  
**Проверка:** `dict.Count() == 0`; `ContainsKey(k) == false` для всех `k`.

---

### 14. Add после Clear - все ключи, корректный Count
`Add(k, v)` для всего входного набора после `Clear()`.  
**Доказывает:** словарь после очистки корректно принимает новые элементы без ошибок.  
**Проверка:** ни одного исключения; `dict.Count() == data.size()`.

---

### 15. TryGetValue - корректные значения после повторного Add
`TryGetValue(k, got)` для всех ключей после повторного Add.  
**Доказывает:** значения после re-Add совпадают с исходными входными данными.  
**Проверка:** `TryGetValue(k, got) == true` и `got == v` для всех пар из входного набора.

---

## Итог

Все 300 проверок пройдены -> каждая из 10 реализаций поведенчески эквивалентна `std::unordered_map` по контракту `IDictionary` на случайных данных размером 10 000 элементов для `TKey = int` и `TKey = std::string`.
