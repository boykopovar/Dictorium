# RedBlackTreeDictionary

`RedBlackTreeDictionary<TKey, TValue>` — упорядоченный словарь на основе **красно-чёрного дерева**. Гарантирует **O(log n)** для поиска, вставки и удаления в худшем случае.

---

## Сложности операций

| Метод | O | Ω | Пояснение |
|---|---:|---:|---|
| `ContainsKey` | O(log n) | Ω(log n) | Поиск по дереву |
| `TryGetValue` | O(log n) | Ω(log n) | Поиск + возврат значения |
| `GetValue` | O(log n) | Ω(log n) | Бросает исключение, если ключ не найден |
| `InsertOrAssign` | O(log n) | Ω(log n) | Поиск места + возможные повороты/перекраски |
| `Add` | O(log n) | Ω(log n) | Вставка нового узла с восстановлением инвариантов |
| `Remove` | O(log n) | Ω(log n) | Удаление узла с восстановлением инвариантов |
| `Count` | O(1) | Ω(1) | Возвращает счётчик элементов |
| `Clear` | O(n) | Ω(n) | Удаляет все узлы |
| `begin` / `end` | O(1) | Ω(1) | Получение итераторов на границы |
| Итерация | O(n) | Ω(n) | Обход в отсортированном порядке |
| `LowerBound` / `UpperBound` | O(log n) | Ω(log n) | Поиск ближайшего ключа |

> **n** — количество элементов в дереве.

---

## Свойства структуры

Красно-чёрное дерево — это бинарное дерево поиска с дополнительной раскраской узлов.

Инварианты:
- каждый узел — **красный** или **чёрный**;
- корень — **чёрный**;
- все листья-`null` считаются **чёрными**;
- у красного узла дети только чёрные;
- на любом пути от узла до листа одинаковое число чёрных узлов.

Благодаря этим ограничениям высота дерева не превышает `2 * log2(n + 1)`.

---

## Как работают вставка и удаление

### Вставка
1. Узел вставляется как в обычное BST.
2. Новый узел окрашивается в красный цвет.
3. Если инварианты нарушены — выполняются перекраска и/или повороты.
4. Корень всегда перекрашивается в чёрный.

### Удаление
1. Узел удаляется как в BST.
2. Если удаление нарушило баланс — выполняются перекраска и/или повороты.
3. Инварианты дерева восстанавливаются за `O(log n)`.

## Особенности

### Упорядоченность
Элементы всегда хранятся в сортированном порядке по ключу. Поэтому дерево удобно для:
- диапазонных запросов;
- поиска ближайшего ключа;
- обхода в отсортированном порядке.

### Память
Каждый узел хранит:
- ключ;
- значение;
- цвет;
- ссылки на `left`, `right`, `parent`.

Память: **O(n)**.

### Сравнение с hash-структурами
- `RedBlackTreeDictionary` даёт **гарантированное O(log n)**.
- Хеш-таблицы обычно быстрее на точечном поиске, но не сохраняют порядок ключей.

---

## Итог

`RedBlackTreeDictionary` подходит, когда нужен **упорядоченный словарь** с гарантированным `O(log n)` для поиска, вставки и удаления. Это хороший выбор для диапазонных запросов и обхода ключей по порядку.
