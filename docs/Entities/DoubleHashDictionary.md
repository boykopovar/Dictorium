# DoubleHashDictionary

`DoubleHashDictionary<TKey, TValue, Hash1, Hash2>` — реализация словаря поверх `std::vector<Entry>` с открытой адресацией и двойным хешированием. Удаление реализовано через tombstone-маркеры (`EntryState::Deleted`).

При коллизии используется последовательность пробирования:

```text
pos = (h1 + i * h2) % capacity
```

где:

- `h1` — основной хэш,
- `h2` — шаг пробирования,
- `i = 0, 1, 2, ...`

Размер таблицы всегда поддерживается простым числом для гарантии полного обхода таблицы.

| Метод            | Сложность | Аморт. сложность | Пояснение |
|------------------|-----------|------------------|-----------|
| GetValue         | O(n)      | O(1)             | `_findIndex` → последовательность двойного хеширования; O(1) в среднем при низком коэффициенте загрузки |
| InsertOrAssign   | O(n)      | O(1)             | `_ensureCapacity` + `_findSlotForInsert`; рехэширование добавляет O(1) амортизированно |
| ContainsKey      | O(n)      | O(1)             | Делегирует в `_findIndex` |
| TryGetValue      | O(n)      | O(1)             | `_findIndex` + копирование найденного значения |
| Add              | O(n)      | O(1)             | `_ensureCapacity` + `_findSlotForInsert`; при дубликате бросает `std::invalid_argument` |
| Remove           | O(n)      | O(1)             | `_findIndex` + установка tombstone-маркера |
| Clear            | O(m)      | O(m)             | `vector::clear` + `resize(11)` |
| Count            | O(1)      | O(1)             | Возвращает `_count` |
| initializer_list | O(n)      | O(n)             | `n` вызовов `Add`; суммарное рехэширование ограничено O(n) |
| _rehash          | O(n)      | O(n)             | Повторная вставка всех `Occupied`-элементов |
| _nextPrime       | O(√n)     | O(√n)            | Поиск ближайшего простого числа |
| _isPrime         | O(√n)     | O(√n)            | Проверка числа на простоту |

> **Худший случай** для поиска/вставки/удаления — **O(n)**. Возникает при большом числе коллизий или плохом распределении хэшей. При коэффициенте загрузки ≤ 0.75 и равномерном распределении хэшей среднее число пробирований стремится к константе.

# Назначение

`DoubleHashDictionary` хранит данные в **едином плоском массиве** без выделения памяти на отдельные узлы, что обеспечивает хорошую кэш-локальность и предсказуемое расположение элементов в памяти.

В отличие от линейного пробирования, двойное хеширование использует индивидуальный шаг пробирования для каждого ключа, что значительно уменьшает primary clustering (образование длинных цепочек коллизий).

Удаление через tombstone-маркеры (`Deleted`) сохраняет корректность цепочек пробирования без физического перемещения элементов.

Рехэширование автоматически:
- увеличивает размер таблицы,
- очищает tombstone-ячейки,
- подбирает новый простой размер таблицы через `_nextPrime`.

Итератор выполняет линейный проход по массиву за:

```text
O(n + m)
```

где:

- `n` — количество элементов,
- `m` — размер таблицы.

При обходе пропускаются:
- `Empty`
- `Deleted`

ячейки.
