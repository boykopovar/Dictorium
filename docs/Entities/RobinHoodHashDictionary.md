# RobinHoodHashDictionary

`RobinHoodHashDictionary<TKey, TValue, Hash>` — реализация словаря поверх `std::vector<Entry>` с открытой адресацией и алгоритмом Robin Hood hashing. Таблица использует PSL (Probe Sequence Length) для выравнивания длины цепочек пробирования. Удаление реализовано через backward shift deletion без tombstone-маркеров.

| Метод            | Сложность | Аморт. сложность | Пояснение |
|------------------|-----------|------------------|-----------|
| GetValue         | O(n)      | O(1)             | `_findIndex` → линейный проход с ранним завершением по PSL; O(1) в среднем при низком коэффициенте загрузки |
| InsertOrAssign   | O(n)      | O(1)             | `_ensureCapacity` + Robin Hood probing; swap по PSL выравнивает длины цепочек; рехэширование амортизируется |
| ContainsKey      | O(n)      | O(1)             | Делегирует в `_findIndex`; используется оптимизация `e.psl < psl` |
| TryGetValue      | O(n)      | O(1)             | `_findIndex` → O(1) в среднем; при нахождении копирует значение |
| Add              | O(n)      | O(1)             | Проверка дубликата + `InsertOrAssign`; бросает `std::invalid_argument` при существующем ключе |
| Remove           | O(n)      | O(1)             | `_findIndex` → backward shift deletion; элементы сдвигаются назад без tombstone |
| Clear            | O(m)      | O(m)             | `vector::clear` + `resize(8)` — уничтожение всех `m` ячеек таблицы |
| Count            | O(1)      | O(1)             | Возвращает поле `_count` |
| initializer_list | O(n)      | O(n)             | `n` вызовов `Add`; суммарное рехэширование не превышает O(n) |

> **Худший случай** для операций поиска/вставки/удаления — **O(n)**. Возникает при вырождении хэш-функции, когда все элементы попадают в один кластер. Однако Robin Hood hashing выравнивает PSL и уменьшает variance длины цепочек, благодаря чему worst-case поведение заметно стабильнее, чем у обычного linear probing.

---

# Назначение

`RobinHoodHashDictionary` хранит все данные в **едином плоском массиве** без динамических выделений памяти на элемент, что обеспечивает высокую кэш-локальность и хорошую производительность поиска.

В отличие от классического linear probing:

- каждый элемент хранит `PSL` (Probe Sequence Length);
- элементы с большим PSL имеют приоритет при вставке;
- поиск может завершаться раньше благодаря проверке `e.psl < psl`;
- удаление выполняется через backward shift deletion без накопления tombstone-маркеров.

Backward shift deletion сохраняет цепочки пробирования компактными и не допускает деградации таблицы из-за «мусорных» ячеек.

Итератор обходит весь массив за **O(n + m)**, пропуская незанятые ячейки (`occupied == false`).
