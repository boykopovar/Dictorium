# Алгоритм `DoubleHashDictionary`

`DoubleHashDictionary<TKey, TValue, Hash1, Hash2>` — реализация словаря на основе **хэш-таблицы с открытой адресацией и двойным хешированием**.

---

## Структура данных

- Входные данные (пары `ключ-значение`):

```json
{
    "key1": 1,
    "key2": 2,
    "key3": 3,
    "key4": 4
}
```

Таблица хранит плоский массив `_table` — `std::vector<Entry>`, где каждый элемент — структура:

```cpp
struct Entry {
    TKey key;
    TValue value;
    EntryState state; // Empty | Occupied | Deleted
};
```

- `_count` — количество активных пар (`Occupied`).
- `_maxLoadFactor = 0.75` — максимальный коэффициент загрузки. При превышении выполняется рехэширование.
- `Hash1` — основной хэш-функтор (по умолчанию `std::hash<TKey>`).
- `Hash2` — второй хэш-функтор, определяющий шаг пробирования.
- `_table.size()` всегда поддерживается простым числом для корректности двойного хеширования.

Для каждого ключа вычисляются:

- основной индекс:

```text
h1 = hash1(key) % capacity
```

- шаг пробирования:

```text
h2 = 1 + (hash2(key) % (capacity - 1))
```

> `h2` никогда не равен `0`, иначе пробирование зациклится на одной ячейке.

### Состояния ячейки (`EntryState`)

| Состояние  | Смысл |
|------------|-------|
| `Empty`    | Ячейка никогда не использовалась. Поиск останавливается здесь. |
| `Occupied` | Ячейка содержит активную пару ключ-значение. |
| `Deleted`  | Ячейка была удалена (tombstone). Поиск продолжается через неё. |

---

## Построение (конструктор)

### Шаги алгоритма:

1. Создаётся вектор `_table` заданной ёмкости.
2. Размер таблицы приводится к ближайшему простому числу через `_nextPrime`.
3. Все ячейки инициализируются состоянием `Empty`.
4. `_count = 0`.
5. Для каждой пары `(key, value)` вызывается `Add`.

> Построение из `n` элементов имеет сложность **O(n)** в среднем случае.

---

## Двойное хеширование

При коллизии следующая позиция вычисляется по формуле:

```text
pos = (h1 + i * h2) % capacity
```

где:

- `h1` — основной хэш,
- `h2` — шаг пробирования,
- `i = 0, 1, 2, ...`

Каждый ключ получает собственную последовательность обхода таблицы.

### Пример

Пусть:

```text
h1 = 3
h2 = 4
capacity = 11
```

Тогда последовательность пробирования:

```text
3 → 7 → 0 → 4 → 8 → ...
```

> В отличие от линейного пробирования, двойное хеширование значительно уменьшает clustering (скопление элементов в длинные цепочки).

---

## Поиск слота (`_findIndex`)

Используется для:

- `ContainsKey`
- `TryGetValue`
- `GetValue`
- `Remove`

### Шаги алгоритма:

1. Вычисляются:
   - `h1`
   - `h2`
2. Последовательность пробирования вычисляется через двойное хеширование.
3. Для каждой позиции:
   - `Empty` → ключ отсутствует, вернуть `capacity`.
   - `Occupied` и `key == искомый` → вернуть позицию.
   - `Deleted` → продолжить поиск.
4. Если таблица полностью обойдена — вернуть `capacity`.

> Tombstone-ячейки (`Deleted`) не прерывают поиск, чтобы цепочка пробирования оставалась корректной.

---

## Поиск слота для вставки (`_findSlotForInsert`)

Используется в:

- `Add`
- `InsertOrAssign`

### Шаги алгоритма:

1. Вычисляются:
   - `h1`
   - `h2`
2. Обход таблицы выполняется по последовательности двойного хеширования.
3. Для каждой позиции:
   - `Occupied` и ключ совпадает → вернуть позицию.
   - `Deleted` → сохранить первый tombstone.
   - `Empty` → вернуть:
     - первый tombstone, если он был найден,
     - иначе текущую позицию.
4. Если таблица полностью обойдена — вернуть `capacity`.

> Переиспользование tombstone-слотов уменьшает фрагментацию таблицы.

---

## Удаление (`Remove`)

Удаление реализовано через tombstone-маркер.

### Шаги алгоритма:

1. Найти позицию ключа через `_findIndex`.
2. Если ключ не найден — вернуть `false`.
3. Установить:

```cpp
_table[pos].state = Deleted;
```

4. Уменьшить `_count`.

> Ячейка физически не очищается, чтобы не разрушать цепочки пробирования других элементов.

---

## Рехэширование (`_rehash`)

Выполняется автоматически при превышении `_maxLoadFactor`.

### Шаги алгоритма:

1. Старый `_table` сохраняется в `old`.
2. Создаётся новая таблица размером:

```cpp
_nextPrime(old.size() * 2)
```

3. `_count` сбрасывается в `0`.
4. Все `Occupied`-элементы заново вставляются через `InsertOrAssign`.

> Tombstone-ячейки (`Deleted`) не переносятся, поэтому таблица автоматически очищается от мусора.

> Размер таблицы всегда поддерживается простым числом. Это гарантирует корректность двойного хеширования и полный обход таблицы при пробировании.

---

## Простые размеры таблицы

Для корректной работы двойного хеширования размер таблицы должен быть простым числом.

Иначе последовательность:

```text
(h1 + i * h2) % capacity
```

может обходить только часть таблицы.

### Пример плохого случая

```text
capacity = 16
h2 = 8
```

Последовательность:

```text
1 → 9 → 1 → 9 → ...
```

обходит только две ячейки таблицы.

### Решение

Метод `_nextPrime()` подбирает ближайшее простое число:

- при создании таблицы,
- при рехэшировании.

Это гарантирует полный обход таблицы.

---

## Итератор

Итератор (`Iterator`) обходит плоский массив `_table`, пропуская ячейки не в состоянии `Occupied`.

### Устройство

- Хранит индекс `_index`.
- Хранит указатель на `_table`.
- Метод `_skip()` пропускает:
  - `Empty`
  - `Deleted`
- `operator++` увеличивает индекс и вызывает `_skip()`.

> Полный проход по таблице имеет сложность **O(n + m)**, где:
>
> - `n` — количество элементов,
> - `m` — размер таблицы.

---

## Сложность операций

| Операция | Средняя сложность | Худший случай |
|---|---|---|
| `Add` | O(1) | O(n) |
| `GetValue` | O(1) | O(n) |
| `Remove` | O(1) | O(n) |
| `ContainsKey` | O(1) | O(n) |
| `Rehash` | O(n) | O(n) |

> Двойное хеширование уменьшает clustering по сравнению с линейным пробированием, поэтому на практике число проб обычно меньше.
