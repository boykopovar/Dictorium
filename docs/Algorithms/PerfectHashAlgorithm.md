# Алгоритм `Perfect Hashing`

## Построение
- Входные данные (пары `ключ-значение`):
```json
{
  "key1": 1,
  "key2": 2,
  "key3": 3,
  "key4": 4
}
```

`count` - Количество ключей

- Функция `int _hash(key, int seed, int tableSize)` для различных наборов `key, seed` обычно дает разный результат (не всегда).
- Функция `int _findSeed(keys, int innerSize)` находит для набора ключей такой `seed`, при котором для каждого ключа из `keys` функция `_hash` дает уникальный результат в таблице размером `innerSize`.


### Шаги алгоритма:
1. Создается массив `buckets`, размером `count`. Где каждый элемент — корзина (список) ключей.
2. Выбирается случайный `globalSeed` (целочисленный).
3. Функция `_hash()` применяется к каждому ключу с параметрами: `seed=globalSeed`, `tableSize=count`.
4. Каждый ключ помещается в корзину, индексом которой в массиве `buckets` является результат функции `_hash()`.
5. Если сумма квадратов получившихся размеров всех корзин превышает `2*count`, очистить корзины и продолжить с шага 2.
6. Для каждой непустой корзины создаётся внутренняя таблица размером `b²`, где `b` — число элементов в корзине. Вызывается `_findSeed()` с параметром `innerSize=b²`, результат сохраняется как `localSeed`.
7. Каждый элемент корзины размещается на позицию `_hash(key, localSeed, b²)` во внутренней таблице.


### Сложность построения

`_findSeed` для корзины размером `b` на каждую попытку сбрасывает внутреннюю таблицу размером `b²` и хеширует `b` ключей. Доминирует сброс:

```
T_findSeed(b) = O(b²)
```

Шаг 5 отвергает `globalSeed` если `∑ bₖ² > 2n`, что гарантирует `∑ bₖ² ≤ 2n`. Суммируя по всем корзинам:

```
T_build(n) = ∑ T_findSeed(bₖ) = ∑ O(bₖ²) = O(∑ bₖ²) ≤ O(2n) = O(n)
```

| Нотация         | Запись | Смысл                               |
|-----------------|--------|-------------------------------------|
| Верхняя граница | O(n)   | ∃ c > 0, ∀n: T(n) ≤ c · n           |
| Нижняя граница  | Ω(n)   | ∃ c > 0, ∀n: T(n) ≥ c · n           |
| Точная оценка   | Θ(n)   | ∃ c₁,c₂ > 0, ∀n: c₁·n ≤ T(n) ≤ c₂·n |

> Построение — O(n) в среднем.

## Доступ к элементу
- Входные данные: `key`

### Шаги алгоритма:
1. Получить значение `globalIndex` как результат функции `_hash(key, globalSeed, count)`.
2. Получить доступ к корзине `buckets[globalIndex]`.
3. Получить значение `localIndex` как результат функции `_hash(key, localSeed, innerSize)`, где `localSeed` и `innerSize` сохранены в корзине.
4. Получить доступ к элементу внутренней таблицы как `bucket[localIndex]` и вернуть значение.

### Сложность поиска

Поиск выполняет ровно два обращения к массиву — независимо от числа элементов `n`:

```
T(n) = a + b = const
```

Из этого следует:

| Нотация         | Запись   | Смысл                           |
|-----------------|----------|---------------------------------|
| Верхняя граница | O(1)     | ∃ c > 0, ∀n: T(n) ≤ c · 1       |
| Нижняя граница  | Ω(1)     | ∃ c > 0, ∀n: T(n) ≥ c · 1       |
| Точная оценка   | Θ(1)     | ∃ c₁,c₂ > 0, ∀n: c₁ ≤ T(n) ≤ c₂ |
| Строго быстрее  | o(log n) | lim(n→∞) T(n) / log n = 0       |

Θ(1) — одновременно является и O(1), и Ω(1).

> Поиск элемента — строго O(1). Это всегда ровно два обращения к массиву, без итераций.
