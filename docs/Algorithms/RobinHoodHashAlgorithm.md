# Алгоритм `RobinHoodHashDictionary`

`RobinHoodHashDictionary<TKey, TValue, Hash>` — реализация словаря на основе **хэш-таблицы с открытой адресацией и алгоритмом Robin Hood hashing**.

Основная идея алгоритма — **выравнивание длины цепочек пробирования**.  
Элементы, находящиеся дальше от своего «идеального» слота, имеют приоритет при вставке.

---

## Структура данных

- Входные данные (пары `ключ-значение`):

```json
{
    "key1": 1,
    "key2": 2,
    "key3": 3,
    "key4": 4
}
```

Таблица хранит плоский массив `_table` — `std::vector<Entry>`, где каждый элемент:

```cpp
struct Entry {
    TKey key;
    TValue value;
    bool occupied;
    size_t psl;
};
```

### Поля `Entry`

| Поле | Назначение |
|------|-------------|
| `key` | Ключ |
| `value` | Значение |
| `occupied` | Флаг занятости ячейки |
| `psl` | Probe Sequence Length — расстояние от идеального слота |

---

## Probe Sequence Length (PSL)

PSL показывает, насколько далеко элемент находится от позиции, вычисленной хэш-функцией.

```cpp
idealIndex = hasher(key) % capacity
psl = distance(currentIndex, idealIndex)
```

Например:

| Ключ | Идеальный слот | Фактический слот | PSL |
|------|----------------|------------------|-----|
| A | 5 | 5 | 0 |
| B | 5 | 6 | 1 |
| C | 5 | 7 | 2 |

---

## Основные поля таблицы

- `_table` — массив ячеек.
- `_count` — количество элементов.
- `_maxLoadFactor = 0.75` — максимальный коэффициент загрузки.
- `Hash` — функтор хэширования (`std::hash<TKey>` по умолчанию).

Стартовый индекс:

```cpp
index = hasher(key) % _table.size()
```

---

## Построение (конструктор)

### Шаги алгоритма

1. Создаётся `_table` заданной ёмкости (по умолчанию `8`).
2. Все ячейки помечаются как `occupied = false`.
3. `_count = 0`.
4. Для каждой пары вызывается `Add`.

> Построение из `n` элементов имеет среднюю сложность **O(n)**.

---

## Алгоритм Robin Hood Hashing

В обычном linear probing новый элемент всегда ищет первый свободный слот.

В Robin Hood hashing используется правило:

> Элемент с большим PSL вытесняет элемент с меньшим PSL.

То есть:

- «бедный» элемент (далеко от дома)
- забирает слот у «богатого» (близко к дому).

Это выравнивает распределение PSL и уменьшает worst-case время поиска.

---

## Вставка (`InsertOrAssign`)

### Шаги алгоритма

1. Вычисляется стартовый индекс:

```cpp
index = hasher(key) % capacity
```

2. Создаётся временный элемент `current`:

```cpp
current.psl = 0
```

3. Линейный проход по таблице:

### Случай 1 — пустая ячейка

```cpp
if (!slot.occupied)
```

Элемент вставляется.

---

### Случай 2 — ключ уже существует

```cpp
if (slot.key == current.key)
```

Значение обновляется.

---

### Случай 3 — Robin Hood swap

Если:

```cpp
slot.psl < current.psl
```

то элементы меняются местами:

```cpp
std::swap(slot, current)
```

После этого вытеснённый элемент продолжает поиск нового места.

---

### Продолжение пробирования

```cpp
index = (index + 1) % capacity;
++current.psl;
```

---

## Почему Robin Hood работает лучше

В linear probing возможно образование длинных кластеров.

Robin Hood hashing:

- выравнивает длины цепочек;
- уменьшает variance PSL;
- делает worst-case поиск заметно стабильнее.

---

## Поиск (`_findIndex`)

Используется в:

- `ContainsKey`
- `TryGetValue`
- `GetValue`
- `Remove`

### Шаги алгоритма

1. Вычисляется стартовый индекс.
2. `psl = 0`.
3. Линейный проход:

---

### Пустая ячейка

```cpp
if (!e.occupied)
```

Ключ отсутствует.

---

### PSL меньше текущего

```cpp
if (e.psl < psl)
```

Поиск можно завершить досрочно.

Почему?

Если элемент с таким PSL уже встретился раньше, искомый ключ не мог оказаться дальше.

Это важная оптимизация Robin Hood hashing.

---

### Найден ключ

```cpp
if (e.key == key)
```

Возвращается индекс.

---

### Следующая ячейка

```cpp
index = (index + 1) % capacity;
++psl;
```

---

## Удаление (`Remove`)

Удаление реализовано через **backward shift deletion**.

Tombstone-маркеры НЕ используются.

---

## Backward Shift Deletion

После удаления элементы сдвигаются назад, чтобы цепочка пробирования оставалась непрерывной.

### Шаги алгоритма

1. Найти элемент через `_findIndex`.
2. Если не найден — вернуть `false`.
3. Начать сдвиг элементов назад.

---

### Условие остановки

Сдвиг прекращается, если:

```cpp
!_table[next].occupied
```

или

```cpp
_table[next].psl == 0
```

Это означает:

- достигнут конец цепочки;
- следующий элемент находится в своём идеальном слоте.

---

### Сдвиг

```cpp
_table[pos] = _table[next];
--_table[pos].psl;
```

Элемент перемещается назад на одну позицию.

---

## Почему backward shift лучше tombstone

В linear probing tombstone-маркеры:

- увеличивают длину поиска;
- накапливают мусор;
- ухудшают locality.

Backward shift deletion:

- сохраняет компактность;
- не создаёт мусор;
- поддерживает короткие цепочки пробирования.

---

## Рехэширование (`_rehash`)

Выполняется при:

```cpp
_count / _table.size() >= _maxLoadFactor
```

### Шаги алгоритма

1. Старый `_table` сохраняется.
2. Создаётся новая таблица в 2 раза больше.
3. `_count = 0`.
4. Все элементы заново вставляются через `InsertOrAssign`.

> Сложность рехэширования — **O(n)**.

Амортизированная стоимость вставки остаётся **O(1)**.

---

## Итератор (`Iterator`)

Итератор обходит `_table`, пропуская пустые ячейки.

### Устройство

Хранит:

```cpp
size_t _index;
const std::vector<Entry>* _table;
```

---

### `_skip()`

Продвигает индекс вперёд:

```cpp
while (_index < _table->size()
       && !(*_table)[_index].occupied)
{
    ++_index;
}
```

---

### `operator++`

```cpp
++_index;
_skip();
```

---

## Сложности операций

| Операция | Средняя | Худшая |
|---|---|---|
| `Add` | O(1) | O(n) |
| `InsertOrAssign` | O(1) | O(n) |
| `ContainsKey` | O(1) | O(n) |
| `GetValue` | O(1) | O(n) |
| `Remove` | O(1) | O(n) |
| Рехэширование | O(n) | O(n) |

---

## Отличия от `LinearProbingDictionary`

| Linear Probing | Robin Hood Hashing |
|---|---|
| Использует tombstone | Использует backward shift deletion |
| Нет PSL | Есть PSL |
| Возможны длинные кластеры | PSL выравнивается |
| Поиск может деградировать | Поиск стабильнее |
| Простая вставка | Вставка со swap |
| Нет раннего завершения поиска | Есть оптимизация `e.psl < psl` |
